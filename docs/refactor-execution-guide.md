# Haven 重构实施手册

> 状态：执行中  
> 制定日期：2026-08-26  
> 前提：个人 Windows 助手；测试版允许破坏性重构；规范、清晰与可验证性优先于功能速度。

本手册将 `stability-refactor-plan.md` 转换为可连续执行的工作顺序。每个阶段完成前，不进入下一阶段；禁止以全局 lint 忽略、长期兼容层或未验证的大爆炸改写换取短期进度。

## 0. 总体执行规则

- 先恢复工程可信度，再调整架构；不要先拆大文件或重置 Git 历史。
- 一个提交只表达一个可审查目标，并附相应测试；跨 crate、契约、安全和数据库变化必须有 ADR。
- 每项破坏性变化必须明确：删除对象、受影响数据、用户重置动作、验证命令和回退方式。
- 新旧实现不得长期并存。新链路验证完成后，同一任务内删除旧实现、旧测试、旧文档入口。
- 当前阶段只做稳定性与可维护性工作，不加入无关的新功能。

## 1. 阶段一：恢复工程基线

### 1.1 目标

让开发、测试和 CI 的结果可重复，并让所有后续重构拥有可信的安全网。

### 1.2 工作项与顺序

| 顺序 | 工作项 | 交付物 | 验收 |
|---|---|---|---|
| 1 | 固定开发环境 | 经验证的 Rust/Node 工具链说明；CI 对齐配置 | 本地与 CI 使用同一版本组合 |
| 2 | 清理 Agent 严格 Clippy | 不含全局 allow 的 Agent 修复 | `cargo clippy --workspace -- -D warnings` 通过 |
| 3 | 测试隔离审计 | 临时目录/内存 DB/依赖注入清单 | 测试不访问真实 AppData、用户配置、网络或全局环境 |
| 4 | 补开发入口 | README、ADR 目录、数据重置与发布说明 | 新开发者可独立启动、测试和重置 |
| 5 | CI 加固 | Windows job、质量门禁、产物检查 | PR 必经门禁完整运行 |
| 6 | 建立提交节奏 | 分支与提交约定、变更模板 | 每项变更可独立审查和回退 |

### 1.3 Agent Clippy 清理拆分

按以下四个独立任务实施，避免在会话恢复路径中混入大范围行为变化：

1. 纯语法整理：折叠嵌套条件、使用 `matches!`、整数倍数判断。
2. 提炼输入对象：为 hooks、inject 等长参数函数建立语义化上下文结构体。
3. 降低类型与数据布局复杂度：缓存类型别名、必要的枚举间接层。
4. 处理 resume / rollback：每次修改都运行对应会话恢复、分支和错误恢复测试。

### 1.4 阶段退出条件

- 格式化、编译、严格 Clippy、后端测试、前端检查、前端测试和生产构建均通过。
- 测试失败时可定位到测试或产品缺陷，不能依赖开发者机器状态重试。
- 现有日志、媒体输出等真实用户目录耦合问题不再出现。

## 2. 阶段二：收敛跨端与持久化契约

### 2.1 优先级

先处理会话域，再依次处理任务、设置、安全确认和工具执行域。会话域横跨 Agent、Memory、App 与 UI，是后续删除兼容逻辑的基础。

### 2.2 每个域的工作项

1. 列出 Tauri 命令、请求/响应 DTO、事件、生产者、消费者和敏感字段。
2. 为稳定业务载荷建立命名 DTO；只在 provider 原始数据和动态工具参数保留 `serde_json::Value`。
3. 规定事件顺序、幂等性与前端状态归并规则，并补跨端测试。
4. 迁移一个完整调用链后，删除旧字段、旧 wire shape 和对应 fallback。
5. 更新架构文档、事件登记和 ADR。

### 2.3 阶段退出条件

- 每一个公开命令和事件均有唯一的定义与登记点。
- 跨端字段仅在边界转换 snake_case / camelCase。
- 没有依靠隐式 JSON shape 或内容比对维持的兼容行为。

## 3. 阶段三：按领域删除旧设计并拆分热点

按如下顺序推进；一次只迁移一个领域。

### 3.1 Agent

- 先拆 hooks、inject、resume、rollback，保持事件是会话恢复唯一权威这一不变量。
- 将循环、投影、队列、恢复和副作用 Hook 分为独立接口；不得重新引入跨层快捷调用。

### 3.2 Memory

- 分离 schema、图谱写入、查询/排序、嵌入和维护任务。
- 仓库层只负责持久化，不能承担 Agent 推理或 UI 展示逻辑。

### 3.3 LLM

- 提取供应商适配器共享的请求、流式、重试、错误分类和用量管线。
- 每个 provider 适配器只保留协议映射；删除旧 provider 名称和配置 fallback。

### 3.4 UI

- 拆分聊天页中的会话状态、事件归并、输入与渲染。
- 以工具类型注册表组织工具结果卡片，禁止继续扩大单一页面或单一卡片组件。

#### P2 范围说明

平台适配按 ADR 0015 暂缓并移出本阶段，不作为 P2 的退出条件；本阶段只验收 Agent、LLM、Memory、聊天 UI 的热点拆分、文档一致性和固定工具链。

### 3.5 统一重构模板

1. 写 ADR：旧设计、目标不变量、影响范围、替代方案、重置与验证方式。
2. 先补行为和负向测试。
3. 建立目标接口，迁移一条完整调用链。
4. 删除旧实现、旧配置、旧测试和旧文档入口。
5. 运行全量门禁，更新架构图、ADR 与发布说明。

## 4. 阶段四：安全、性能与发布验收

- 收紧 Tauri CSP，并验证模型文本渲染、外链打开与 IPC 的安全边界。
- 为文件路径、重解析点/符号链接、授权继承、取消/超时和子进程生命周期建立回归矩阵。
- 为流式、缓存、后台任务和大文件路径定义容量上限、并发模型、取消语义和压力测试。
- 用全新数据目录完成安装、启动、配置、会话、工具、升级重置和卸载验证。
- 输出发布说明：已删除能力、必须重置的用户数据、已知限制和回滚方案。

## 5. Git 历史重置（最后且独立执行）

仅在稳定版本验收通过后执行，不能与代码重构混在同一提交中。

1. 导出源码快照、可复现构建产物、发布说明和必要的审计记录。
2. 归档旧仓库或保留受保护归档分支，明确旧克隆的处理方式。
3. 创建无父提交的新默认分支，并建立新的提交规范、分支规则、CI 门禁和 ADR 目录。
4. 在确认远端、标签、发布产物和已有克隆影响后，强制更新远端默认分支。
5. 从全新克隆执行一次完整构建与发布验证。

## 6. 每次工作前后的检查

开始前：确认当前阶段、读取相关 ADR/规范、列出要删除的旧行为与验收标准。

完成后：运行相关测试和完整门禁、确认旧入口已删除、更新文档、记录用户可见变化及重置说明，并按 [Git 提交流程](git-workflow.md) 将本轮可审查改动提交。
