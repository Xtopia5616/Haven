# 0074：工具调用前置说明与确定性回退

## 背景

Haven 的模型响应已经能够同时携带普通 assistant 文本和工具调用，但模型有时会直接发起工具调用，导致聊天卡片只显示工具名，任务甚至把原始命令显示成任务标题。模型生成的自然语言说明适合做用户体验层的操作意图，但不能作为 UI 必然可见的契约。

## 决定

1. 在 `MAIN_SYSTEM_PROMPT` 中定义跨工具一致的规则：对可见工具调用，模型先用普通 assistant 文本输出一句简短说明；不得使用 reasoning/thinking 内容代替，也不得泄露完整命令、JSON、密钥或隐藏思考。
2. UI 将模型说明视为优先展示内容；如果该 ReAct thought block 没有可见文本，聊天工具卡显示统一的 `调用工具` 回退标签。
3. 任务与聊天卡片共用同一个回退常量。后台任务的原始命令只在详情中显示，不能自动成为任务主标题；定时任务已有的标题/正文仍优先作为用户提供的任务描述。
4. 不新增后台 action 数据库字段或 IPC 事件。后台 action 可以脱离会话运行，且现有 action DTO 不携带 assistant thought，因此任务使用同一确定性回退是跨重启也可靠的边界。

## 替代方案

- 只修改每个工具的描述：无法覆盖所有工具，且无法保证任务等脱离工具 schema 的 UI 一致。
- 增加一个小模型专门生成意图：增加延迟、成本和失败面，且仍需要 UI 回退。
- 让模型把意图写入后台 action 持久化字段：需要扩展数据库、IPC 与恢复契约，当前收益不足以抵消边界复杂度。

## 影响

模型通常会在工具卡前显示更自然的操作说明；没有说明时，两个入口都会稳定显示“调用工具”。原始 shell 命令仍可在任务详情中审计。这个方案不保证模型每次都遵守提示词，但保证 UI 在该情况下有可见的确定性状态。

## 验证

- `corepack pnpm run check`
- `corepack pnpm run test:run`
- `corepack pnpm run build`
- `cargo fmt --all -- --check`
- `cargo test --locked -p haven-common`

## 回滚与数据重置

回滚代码即可恢复旧展示逻辑；本变更不修改数据库 schema、不新增配置，不需要删除或重建 `haven.db`。
