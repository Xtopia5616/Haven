# ADR 1384：显式重新应用已保存的运行时配置

## 状态

已实施 — 2026-10-24。R02 增加按运行时目标跟踪 apply 代次，并允许 Settings 对失败或未执行目标显式重试。

## 背景

`ConfigService` 在运行时 apply 失败时仍保留已写入配置。相同编辑之后是 no-op，因此不能依靠重复保存相同值重试失败的目标。Settings 还有序列化的多阶段计划；一个阶段失败会停止后续阶段，而先前成功的目标不应仅为重试失败项而重复执行。模型命令也通过共享配置 gate 执行 Router 更新，必须使用相同恢复语义。

## 决定

1. `RuntimeConfigCoordinator` 继续拥有配置 apply gate，并增加有界的进程内状态，按每个运行时目标记录期望配置版本、最后完整应用版本、结果和净化原因。结果区分已应用、待处理、可重试和重启后生效；进程启动时从配置版本 0 作为完整应用基线。
2. `get_settings_runtime_apply_status` 返回这些目标状态；`reapply_saved_settings` 在同一配置 gate 内读取最新持久快照，只重跑失败或尚未执行的 live phase。重试成功的旧版本不能越过新编辑：两者由同一个 gate 串行，取得 gate 后才读取快照。
3. 阶段完成后立即从目标恢复计划中移除。失败时保留失败 phase 与其后尚未执行的 phase；Router publish 需要重新准备 Router，因此重试会补上 `RouterPrepare`。已完成的无关目标不会被重复执行。
4. 新编辑覆盖其命中的目标恢复状态；不相关目标的待处理状态继续保留。相同值的 no-op 不会隐式触发重试。重启专属目标仅显示 `pending_restart`，不由 live retry 命令执行。
5. Security 重试仍重新校验资源根与 execution workspace。状态仅在进程内保存；重启时各 runtime owner 从已保存配置初始化，因此旧进程状态无需持久化。
6. Settings 显示目标、期望版本、最后完整应用版本、结果和净化原因，并提供显式“重试已保存配置”操作。模型配置编辑失败也会进入同一目标状态表。

## 影响与兼容性

新增两个 Tauri Settings 命令和一个响应 DTO，不改配置文件、数据库 schema、凭据或 session event。配置依然先持久化再 apply；失败不回滚配置。部分副作用可能已发生，状态中的 actual version 表示最后完整应用版本；`retryable` 表示目标还需重试，不能用它推断目标在运行时完全没有部分变化。Router 与媒体的原子可见边界仍由 R03 处理。

## 替代方案

- 要求用户编辑任意字段触发 apply：拒绝；会产生无关配置变化，并不表达显式重试意图。
- 重启前重跑完整 Settings 计划：拒绝；会重复已成功目标的副作用，且不能显示实际代次差异。
- 持久化 apply 状态：拒绝；运行时状态在重启时由当前已保存配置重建，不需要新增第二份持久事实。

## 验收与限制

验证了失败状态、目标版本、完成阶段跳过、基于最新快照构造 retry plan，以及 UI 对 pending target 的显式重试。适用的 Rust/UI/IPC 门禁结果记录在本轮交付说明。重试期间遇到真实 Windows 系统行为仍由 §5.1 发布验收覆盖；R03 的模型与媒体混合代次影响仍待单独验证。
