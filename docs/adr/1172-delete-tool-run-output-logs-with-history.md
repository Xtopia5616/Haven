# ADR 1172：让 ToolRun 全量输出日志跟随历史记录清理

## 状态

已采纳并实施。

## 背景

Shell 的完整输出日志保存在 Haven runtime Temp 下，并由持久化 ToolRun 的 `log_path` 引用。用户删除单条终态 ToolRun 或清空终态历史时，数据库记录被移除，但日志文件仍留在磁盘。进程在数据库提交删除后、文件清理前崩溃也会留下同类孤儿文件。

## 决策

- ToolRun 日志的删除生命周期跟随其 ToolRun 历史行。删除单条记录或批量清理成功提交后，清理该记录对应的日志；启动恢复时删除没有持久化日志引用的孤儿文件。
- 清理不使用数据库的 `log_path` 作为删除目标。日志叶名称只由规范 `toolrun-*` 身份构成，并固定在 `tool-run-logs/<tool_run_id>.log`。
- 删除通过打开并持有的 `DirectoryCapability` 相对日志目录执行；只处理规范 ToolRun 文件名，不匹配的文件保留。目录无法安全打开或数据库引用查询失败时不删除文件并记录脱敏 warning。
- 单条删除与批量删除先提交数据库，再 best-effort 删除文件。两者之间若进程崩溃，下一次启动的孤儿扫描会重试；文件清理失败不恢复已经删除的历史行。

## 替代方案

- 信任并删除持久化的任意 `log_path`：拒绝，数据库路径不能扩大文件删除权限。
- 清空整个 Temp 日志目录：拒绝，仍被保留的 ToolRun 可能继续引用其中日志，目录也可能包含非 ToolRun 文件。
- 仅在用户删除历史时清理：拒绝，不能处理数据库提交后进程崩溃造成的孤儿文件。

## 影响与迁移

不改变 schema、IPC、配置、ToolRun 身份或历史保留策略，无需重置数据库或配置。仍保留的终态 ToolRun 日志继续可用；用户删除对应历史后日志随之失效并被清理。启动扫描只删除 runtime Temp `tool-run-logs` 中没有数据库 `log_path` 引用的规范 ToolRun 文件名。

## 验证

- Memory store 查询只返回仍持久引用输出日志的 ToolRun ID。
- 文件清理测试确认 orphan 被删除、仍被引用的日志及无关文件保留，非规范 ID 不会生成删除目标。
- 执行受影响 crate 与 workspace 的适用编译、Clippy、测试门禁。
