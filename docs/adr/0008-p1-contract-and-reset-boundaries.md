# ADR 0008：P1 契约、依赖与重置边界

日期：2026-08-26  
状态：已采纳

## 背景

录音/转写事件虽已在 Rust 端使用结构体，却没有前端唯一的字段转换与事件目录；同时配置加载器和
定时任务恢复仍静默重写已删除的工具、采集设置。这会让升级后的运行语义取决于历史数据，而非当前
契约。架构中的 crate 依赖方向也仅靠人工维护。

## 决定

录音/转写的所有公开事件使用命名 Rust DTO，并在 `ui/src/lib/contracts/recording.ts` 唯一进行
snake_case 到 camelCase 的转换。事件目录明确事件顺序、可丢失性、关联 ID 与敏感字段限制。

删除旧顶层 `[audio]` 和已删除 `tool_settings` 项的运行时迁移；加载器备份旧配置后采用安全默认值。
删除待执行定时任务的旧工具名转换；旧数据库中的此类任务不再被改写，用户应按发布说明重置数据。
Phase-7 `canonical/history` ReAct 快照不再重建为事件日志；未命名的媒体 capability provider 也不
再读取 `[media.*]` 的本地凭据，必须引用 `llm.providers`。检测到旧媒体 provider 名或凭据时，配置
加载器备份整个配置并使用默认值。CI 运行内部 crate 依赖 allow-list，避免反向依赖无意引入。

## 替代方案

保留自动重写可以减轻升级成本，但会长期保留不透明的安全与执行语义；将转换分散在页面也会制造
第二个 wire 真源。两者均被拒绝。

## 影响、验证与回滚

旧配置会生成 `.bak`，而不再继承其值；旧定时任务需重建。验证包括配置重置单元测试（含媒体 provider
名称与凭据）、DTO 序列化
与前端契约测试、依赖方向脚本以及全量质量门禁。若必须回滚，可恢复备份配置或使用此前版本，不能
在新版本重新加入静默迁移。
