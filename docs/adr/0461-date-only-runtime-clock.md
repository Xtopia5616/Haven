# ADR 0461：提示上下文仅注入本地日期，精确时间按需读取

## 状态

已接受（2026-10-04）。

## 背景

ADR 0436 从会话恢复时重建的 runtime snapshot 中删除了全部时钟值。产品需要模型在会话开始或恢复时知道当天日期，同时避免每次恢复都因秒级时间改变会话上下文、降低可复用的提示缓存前缀。

现有 `system.info` 操作的 `category=locale` 已能按需返回本地时间、UTC 时间、时区偏移和 locale。

## 决定

1. 在 runtime snapshot 中加入本地日期，格式为 `YYYY-MM-DD`，不包含时分秒或时区。
2. 该日期位于 `SESSION CONTEXT` 动态后缀；同一当地日期内恢复会话时日期文本保持不变，跨日后更新日期。
3. 精确本地/UTC 时间、时区，以及长会话中可能已跨日的当前日期，继续通过 `system.info` 的 `category=locale` 按需获取，不新增重复工具。

## 替代方案

- 不在提示上下文提供日期：缓存最稳定，但模型缺少常用日期基准；不采用。
- 在每轮提示中注入当前时分秒：会让动态后缀随时间持续变化；不采用。
- 新增独立的时间工具：现有 `system.info(category=locale)` 已提供所需权威值；不重复定义能力。

## 影响与验证

同一当地日期内，日期字段不会引入新的文本变化；跨日恢复时动态会话上下文会变化一次。Provider 缓存仍由各 provider 的前缀匹配策略决定，本 ADR 不承诺固定缓存命中率。验证：Rust workspace 格式、check、严格 Clippy、全量测试，以及 UI check、测试和生产构建均通过。

## 回滚

删除 runtime snapshot 的 `local_date` 字段并还原相应提示说明即可；无数据库、配置或用户数据迁移。
