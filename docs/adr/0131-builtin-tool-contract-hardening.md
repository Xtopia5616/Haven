# ADR-0131：内置工具结果与边界契约加固

## 背景

内置工具的输出同时有结构化 JSON 和 `ToolResult` 顶层元数据两层契约。审计发现，进程、环境变量、剪贴板、Shell、窗口、系统信息和 HTTP 等路径中，部分工具只在 JSON 内标记 `truncated`，没有同步顶层字段；HTTP 的响应字节上限也可能静默丢弃尾部，且响应头可能携带 cookie 或认证材料。另有若干入口的 native 参数约束弱于模型可见 schema。

## 决定

1. 使用 `ToolResult::from_output` 作为“成功且可能截断”的统一构造入口。它会从结构化输出推断截断状态，并保证 JSON 与顶层标记至少在 `true` 方向一致。
2. HTTP 读取上限返回显式的字节截断状态；响应输出过滤认证、cookie 和 API key 类响应头。
3. `schedule` 的 native 入口复用与 schema 相同的 `1..=86400` 延迟边界；当目标工具在全局 registry 中可见时，在创建定时任务时先执行目标 schema 校验。
4. 输入回显不再写入实际键入文本；`ask`、`notify`、MCP/Skill loader 的输入 schema 增加严格对象边界和合理长度/数量上限。
5. prompt 的失败恢复指导遵循 `retry_safety`：未知超时或有副作用的失败不得盲目重放；桌面操作采用“观察—执行—复核”提示，定时调用明确是未来的独立执行。

## 替代方案

- 仅依赖各工具自行维护顶层与嵌套字段：已证明容易漂移，故不采用。
- 统一把所有结果改成一个全新的 envelope：会造成不必要的 UI、历史和 MCP 兼容迁移，本轮不采用。
- 只收紧 JSON schema、不收紧 native 入口：内部调用仍可绕过边界，故不采用。

## 影响

模型、执行器和 UI 对截断结果得到一致信号；HTTP 大响应和敏感响应头的暴露面降低；定时任务会更早发现错误参数。输入工具卡片显示脱敏占位符，不再显示实际键入内容。长度上限会拒绝超限的 ask/notify/loader 参数，而不是无限扩张上下文或 UI。

## 验证

- `cargo test --locked -p haven-tools`
- 覆盖结果截断双层同步、HTTP 字节上限、敏感响应头、窗口双重筛选、定时任务负数延迟等回归测试。

## 回滚与数据

本变更不修改数据库 schema，不需要重置数据。若需回滚，可回退本 ADR 对应代码提交；历史中已写入的脱敏结果不会恢复为原始输入。
