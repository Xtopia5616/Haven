# ADR 0983：拒绝将 128 位整数映射为 IPC `number`

## 状态

已采纳并实施。

## 背景

Rust→TypeScript IPC 生成器把 Rust 原语映射为 TypeScript 类型。JSON 数值进入 UI 后成为 JavaScript `number`；`i128` 和 `u128` 的值域超出 binary64 的精确整数范围，直接映射会生成无法兑现的精度契约。当前生成 DTO 没有使用这两种字段类型，但生成器允许未来契约悄然引入它们。

## 决定

生成器对 `i128`、`u128` 失败关闭。需要跨 IPC 传递这类值时，调用方必须为具体 DTO 选择十进制字符串，或使用有明确范围约束的窄整数类型；不全局改变现有 Rust 整数字段的 JSON wire 形状。

现有数值 DTO 仍需在具体边界遵守领域取值范围；使用 `number` 不代表无限整数精度。

## 影响与验证

- 当前生成 TypeScript 文件和 IPC wire contract 不变。
- 单元测试锁定现有原语映射，并确认 `i128/u128` 被拒绝。

## 回滚

恢复生成器对 `i128/u128` 的 `number` 映射并移除对应测试。该变更不影响已生成 DTO 或持久数据，无需迁移。
