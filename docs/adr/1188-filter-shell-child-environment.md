# ADR 1188：过滤 Shell 子进程继承环境

## 状态

已采纳并实施。

## 背景

前台与后台 Shell 之前继承 Haven 主进程的完整环境。主进程由开发终端启动时可能带有 provider/API token、云服务凭据、Python/PIP 路径覆盖和其它应用级变量。Shell 命令并不需要这些变量即可获得用户级命令行体验；不受信任的命令可以通过输出、子进程或网络请求意外传播它们。

## 决定

- Shell spawn 时先清空环境，再恢复运行基线（`PATH`、系统目录和临时目录）、常用用户上下文/终端/区域设置，以及显式配置的 HTTP(S)/SOCKS 代理变量。
- Haven 自动检测到的本地代理仍只在用户未设置代理变量时注入；显式代理配置优先。
- 其它继承变量不传递，特别是 provider/cloud 凭据与 Python/PIP import、安装源覆盖。Skill 与 MCP stdio 继续使用更窄的 runtime baseline 和各自的显式配置，不因 Shell allowlist 扩大。
- 这是减少环境变量意外传播的措施，不是 OS 进程沙箱。Shell 仍以当前 Windows 用户运行；授权策略仍决定 Shell 是否可启动以及网络能力是否需确认/拒绝，但该过滤器不能限制进程读取用户文件或直接访问网络。
- 依赖未列入白名单变量的命令不再隐式继承它们。需要应用密钥的场景应使用显式的、按 capability 授权的凭据注入设计；本 ADR 不新增通用环境注入入口。

## 替代方案

- 继续继承完整环境：拒绝，父进程中的 provider/cloud 凭据和任意运行时覆盖会进入模型可调用的命令。
- 只删除已知秘密变量：拒绝，新凭据名称和运行时覆盖容易遗漏；明确白名单更易审计。
- 只保留 runtime baseline：拒绝，交互式 Shell 通常需要用户目录、终端/区域设置及用户显式配置的代理。

## 影响与迁移

自定义环境变量、Python/PIP 覆盖等不再自动进入 Shell 子进程。显式代理、用户目录和命令查找所需的基线变量继续可用。不存在配置或数据库字段变化，无需数据重置。ADR 1182 中“通用 Shell 保留交互式用户环境契约”的历史决定由本 ADR 的过滤式交互环境取代。

## 验证

- Platform 过滤测试覆盖保留的 Shell 用户上下文/代理变量及被丢弃的 provider/cloud 凭据和 Python/PIP 覆盖。
- Tools 子进程探针验证实际 spawn 环境保留白名单值并丢弃哨兵凭据/覆盖值，测试使用传入 fixture，不修改全局环境或访问网络。
- 运行 workspace Rust 测试、严格 Clippy、格式检查、ADR 索引与依赖边界检查，以及 `git diff --check`。
