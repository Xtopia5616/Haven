# ADR 1413：权限确认展示实际调用参数并折叠疑似凭据

## 状态

已采纳并实施。

## 背景

权限弹窗此前只显示通用摘要。Shell 命令、HTTP 请求、文件目标及扩展参数等具体内容被留在后端，用户无法据此判断即将执行的操作，确认可能退化为盲批。

## 决定

- pending `confirm` 和 `scheduled_confirm` 事件携带本次调用的 `tool_input`；Ask、已决和过期事件不携带该字段。授权 receipt、continuation 与执行权仍由后端持有。
- 权限弹窗默认展示结构化参数。复用可展开的 JSON 视图，普通字段按默认深度展开。
- 凭据字段名及常见内嵌凭据模式使用 best-effort 识别；被识别的值默认折叠，用户可以展开查看。识别结果只改善默认显示，不是安全过滤器，也不声称能发现所有秘密。
- 操作摘要不再声称参数被隐藏，而是提示用户检查下方调用参数。MCP 管理调用的参数摘要仍可脱敏；待审批详情视图接收原始调用参数，以便按字段折叠。
- 不把调用参数写入普通日志、错误文案或测试中的真实凭据 fixture。参数在渲染进程内可见；折叠是用户界面行为，不是对 renderer 的保密边界。

## 替代方案

- 继续仅显示通用摘要：拒绝，用户无法审查将执行的具体内容。
- 永久遮掉疑似凭据：拒绝，用户无法检查命令或请求里实际传入的值。
- 让前端敏感值扫描承担安全防护：拒绝，启发式模式会漏报；真正的权限校验与执行授权仍必须由后端完成。

## 影响与回滚

变化仅涉及 Tauri 事件、前端映射和权限弹窗，不改配置或数据库 schema，无需重置数据。session 的 interaction event 已保存原始工具参数；新增的 `tool_input` 是 pending UI 投影字段。回滚时移除该字段及参数视图，恢复只显示摘要的提示，不需要数据迁移。

## 验证

- UI 测试覆盖普通参数可见、凭据样式的参数默认折叠并可展开，以及敏感字段名和内嵌凭据检测。
- Rust 投影测试确认 pending 请求包含 `tool_input`，且不投影授权 receipt。
- IPC 生成契约、Rust workspace 门禁、UI 检查与 UI 测试覆盖事件和展示路径。
