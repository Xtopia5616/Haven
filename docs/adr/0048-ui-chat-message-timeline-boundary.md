# ADR 0048：UI 聊天消息时间线边界

## 背景

聊天路由页除了状态与事件编排，还直接包含欢迎态、消息列表、工具卡片入口、后台任务
等待提示和错误继续按钮的模板与样式。消息时间线属于独立的 UI 渲染职责，继续放在
路由页会扩大页面热点并降低渲染边界的可审查性。

## 决定

- 新增 `ui/src/lib/ChatMessageTimeline.svelte`，承载欢迎态、`ChatBubble` 列表、
  后台任务等待提示和错误继续按钮。
- 组件通过 props 接收消息、用量查询和用户操作回调；路由页继续拥有消息 store、
  滚动容器、滚动跟随策略以及 ask/context-menu/continue 的业务处理。
- 保持 `.message-list` DOM 锚点、懒渲染滚动测量、动画、快捷键提示、工具卡片参数和
  ask 交互回调契约；不改变 IPC、持久化或消息数据结构。

## 替代方案

- 继续把时间线模板留在路由页：会延续页面状态与渲染职责混合，拒绝。
- 让时间线组件直接读取消息/usage store：会形成第二个状态入口，拒绝。
- 同时移动滚动容器与滚动控制：会扩大本片行为变化面，暂不采用。

## 影响

这是 UI 内部渲染边界拆分。消息顺序、工具卡片展示、空态/错误态和滚动行为保持不变，
不需要数据或配置迁移。

## 验证

```text
corepack pnpm --dir ui run check
corepack pnpm --dir ui run test:run
```

## 回滚与重置

代码回滚时删除 `ChatMessageTimeline.svelte`，恢复 `+page.svelte` 中的消息时间线
模板与样式；本次不改变持久化数据或配置，不需要用户重置。
