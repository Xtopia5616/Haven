# ADR 0409：限制 Provider 流索引与响应项数量

- 状态：已采纳
- 日期：2026-09-30
- 范围：OpenAI-compatible 工具调用流与 Anthropic Messages 内容块流

## 背景

Provider 流索引来自外部响应。OpenAI-compatible 适配器将有符号索引直接转换成 `usize`，随后按索引逐项扩展工具调用向量；负值会变成巨大的无符号值。Anthropic 适配器也会按内容块索引逐项扩展状态向量。恶意或异常响应因此可能触发超大分配。

## 决定

- 每个 OpenAI-compatible 流最多聚合 128 个工具调用槽位；索引必须非负且小于 128，超界时以 `InvalidResponse` 终止当前流。
- 每个 Anthropic 流最多开始 128 个内容块；索引必须小于 128，重复开始同一索引或超界事件以 `InvalidResponse` 终止当前流。
- 所有 Anthropic 内容块事件都验证索引范围；重复 stop 不重复写布局数据。

## 替代方案

- 仅检查非负索引：仍允许 provider 控制向量扩展到任意大的位置。
- 使用稀疏映射代替向量：可以避免按索引补齐，但仍需限制响应项数量，而且改动范围更大。

## 影响

超出 128 项的流式响应不再部分接受，而是作为无效响应结束。常规工具调用及 Anthropic 内容块保持原有映射行为。没有数据库、配置或 IPC 契约变化，无需重置用户数据。

## 验证

- OpenAI 索引拒绝负值、允许最后一个有效索引并拒绝上限值。
- Anthropic 索引与内容块数量边界测试覆盖上限内和上限外。
- 运行 LLM crate 测试、workspace 格式/编译/Clippy 检查，以及适用的仓库门禁。

## 回滚与重置

回滚本 ADR 与对应流索引验证、数量上限即可恢复原有行为；无需重置用户数据。
