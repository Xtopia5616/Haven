# ADR 0452：文件变更操作的取消提交边界

- 状态：Implemented
- 日期：2026-10-04
- 范围：`files.create_dir`、`files.copy`、`files.move`
- 关联：ADR 0002、0015

## 背景

创建目录、复制和移动操作原先在文件系统操作完成后检查取消令牌。取消若在操作期间到达，磁盘已经改变，但工具却返回“已取消”，调用者无法判断该操作是否提交。与此相反，write/edit/patch 在开始替换之前检查取消。

## 决定

1. 三种文件变更统一在开始前检查取消；已取消时不启动文件系统操作。
2. 一旦文件系统操作开始，就等待其真实结果。令牌此时被取消也不把成功提交报告成取消；I/O 错误仍按原样返回。
3. FilesTool 现有路径解析、授权和风险门禁保持不变。跨卷 move 继续使用现有 copy 后 remove 的回退逻辑。

## 影响

这消除了“副作用已发生但结果称已取消”的矛盾，并保留了操作开始前取消的快速退出。数据库、配置、IPC 和用户数据格式不变，无需重置。跨卷移动若复制成功而源文件删除失败，仍会报告 I/O 错误并保留两份文件；本 ADR 不更改该既有失败语义。

## 验证

使用临时目录验证预取消时目录/副本/目标均未创建且 move 源文件完整保留；用可控异步操作验证开始后取消仍返回已提交结果。运行 `haven-tools` 单元测试和 workspace 门禁。

## 回滚

如需回滚，只恢复这三种操作原先的取消检查。不得在文件系统操作成功后重新添加令牌检查，否则会重新引入提交状态与工具结果不一致的问题。
