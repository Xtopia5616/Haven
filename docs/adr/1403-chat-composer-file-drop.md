# ADR 1403：在聊天输入区拖放加入附件

## 状态

已采纳并实施。2026-10-25 前端检查、169 个测试文件（1500 项测试）与生产构建通过；Windows WebView2 桌面拖放验收仍待完成。

## 背景

聊天输入区已有文件选择器和粘贴图片入口，并负责附件分类、预览、数量/大小限制及提交。用户也需要从资源管理器直接把图片、音频或文件拖入输入区。

## 决定

1. `Composer` 输入卡片是文件拖放区域；拖入文件时显示明确的投放提示，松开后加入现有附件草稿。
2. 拖放与文件选择器共用图片/普通文件分类和读取流程，继续使用既有上限、预览、移除及提交语义。非文件拖动不改变输入内容。
3. 拖放只作用于输入卡片，不新增 Tauri 命令、IPC、持久化字段或资产生命周期；附件仍仅在用户提交消息时进入现有后端入口。
4. 拖放状态留在 `Composer`，因为它拥有同一附件草稿与读取计数；不另建组件或第二份附件状态。

## 替代方案

- 在页面级捕获所有文件拖放：拒绝，页面其他区域不会变成附件投放目标，也可能覆盖现有页面交互。
- 为拖放单独实现一套附件处理：拒绝，会复制 MIME 分类、上限与读取状态，容易与文件选择器行为漂移。
- 使用 Tauri 文件系统路径直接上传：拒绝，现有附件入口以 renderer 提交的媒体负载进入 host 校验与持久化，不应绕开该边界。

## 影响与回滚

无需数据库、配置或缓存重置。回滚时移除输入卡片的拖放事件和提示即可；文件选择器、粘贴图片及既有附件提交不变。

## 验证

- 前端回归测试覆盖拖入文件、提示状态、默认浏览器行为拦截及通过原有 payload 提交。
- `corepack pnpm run check`：0 错误、0 警告。
- `vitest run --maxWorkers=4 --reporter=dot`：169 个测试文件、1500 项测试通过。
- `corepack pnpm run build`：通过并生成 CSP manifest。
- 真实 Windows WebView2 文件拖放仍需在桌面应用中验收。
