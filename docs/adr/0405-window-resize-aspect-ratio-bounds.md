# ADR 0405：主窗口缩放比例边界

- 状态：已采纳（2026-09-30）
- 关联：`docs/ui.md` §10.11（横版工作台与竖版手机布局）

## 背景

主窗口允许用户自由缩放，但极窄或极宽的比例会让工作区布局超出当前桌面界面的使用范围。CSS 响应式断点负责选择布局，不能阻止原生窗口进入这些比例。

## 决定

1. 主窗口继续允许缩放，WebView 客户区宽高比限制在 2:3 至 21:9（含边界），与 UI 的竖向和超宽布局范围一致。
2. Windows 主窗口在 `WM_SIZING` 中调整正在拖动的边，使宽高比停在最近边界；比例判断使用客户区尺寸，与 CSS viewport 对齐。普通 16:9、16:10、4:3 和方形窗口仍可自由缩放。
3. 最大化时，如果显示器工作区宽高比超出范围，则在工作区内居中显示最接近边界的窗口尺寸。Windows 限制代码使用独立模块和 `SetWindowSubclass`，在 Tauri setup 的窗口线程安装，并在 `WM_NCDESTROY` 移除。
4. 原生约束安装失败时记录错误，并将主窗口设为不可缩放，避免退化为无比例限制的状态。

## 替代方案

- 只靠 CSS：可以改变内容排布，无法阻止原生窗口继续进入超出范围的比例。
- 等 `Resized` 事件后恢复尺寸：窗口已越界并可能闪烁，也不能保证拖动时体验稳定。
- 完全禁用窗口缩放或固定 16:9：会移除范围内的有效布局选择，因此不采用。

## 影响与验证

- 不改变窗口默认尺寸 1280×720、数据库、配置 schema 或前后端 IPC 契约；无数据重置要求。
- 比例计算与 RECT 调整保持为纯函数并覆盖范围内尺寸、水平与垂直边界、角部锚点和超宽/竖屏显示器最大化的单元测试。Windows FFI 限于主窗口 HWND、同步窗口消息以及客户区/工作区尺寸查询；安装失败会关闭缩放并记录诊断。
- 自动化测试不替代桌面交互验收；发布前仍需在 Windows 桌面验证四边与四角拖动、最大化、不同 DPI/显示器及 2:3、21:9 边界。

## 回滚

移除窗口 subclass 安装并恢复单纯的 Tauri `resizable` 行为即可。回滚不要求数据库或配置重置。
