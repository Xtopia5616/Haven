# ADR 0106：统一记忆中心的内容与操作边界

日期：2026-09-08
状态：已采纳

## 背景

记忆页原先将“长期记忆”和“记忆检索”作为两个并列区域展示。两者并不是同一层级的概念：长期记忆描述结构化事实内容，检索描述访问记忆的操作。并列布局还重复了搜索工具栏和结果上下文，用户需要先判断应该进入哪一块。

## 决定

1. 记忆页统一为一个“记忆中心”入口，顶部提供一个搜索框和记忆范围选择。
2. 记忆内容仍分为两种类型：结构化事实（`fact`）和过去的对话片段（`episode`）。不合并数据库表、embedding 域或内部 `MemoryKind` 语义。
3. 没有搜索词时展示可浏览、添加和删除的已保存事实；选择“过去的对话”时展示搜索引导。
4. 搜索时复用现有 `recall_memory` 命令。选择“全部记忆”时分别执行一次有界的事实和对话检索，并在结果中标明内容类型，不比较两个领域不兼容的原始分数。
5. 保留 `list_facts` 作为事实管理所需的完整 DTO 入口，保留 `recall_memory` 作为相关性结果入口；本次不修改 Tauri wire shape、数据库 schema 或 `MemoryRetriever`。

## 替代方案

- 继续保留两个页签：实现改动较小，但把“内容类型”和“检索操作”混在同一层，仍然造成重复入口。
- 将事实和对话片段合成一种持久化记录：会丢失事实的来源、置信度、标签和删除语义，也会让向量域和权限边界变模糊，因此不采用。

## 影响与验证

新增 `MemoryCenter.svelte` 作为 UI 编排层；`LongTermFacts.svelte` 和 `MemoryRecall.svelte` 保留各自的事实管理与结果展示职责。既有 IPC、数据库和 Agent 召回路径不变。

重点验证：

```text
corepack pnpm --dir ui run check
corepack pnpm --dir ui run test:run
corepack pnpm --dir ui run build
```

## 回滚与重置

回滚对应提交即可恢复原先的并列布局。无需数据库、配置或缓存重置。
