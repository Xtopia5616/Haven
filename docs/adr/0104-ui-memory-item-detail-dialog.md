# ADR 0104：统一工作区条目卡片并将记忆详情移入弹窗

日期：2026-09-08
状态：已采纳

## 背景

任务工作区已经使用“卡片预览 + 点击查看详情”的渐进披露模式，而长期记忆仍在列表右侧常驻详情面板中。两种工作区的卡片外壳、悬停状态和操作栏各自维护，导致交互模型和视觉层级不一致，也让记忆列表在窄窗口中占用过多固定空间。

## 决定

1. 长期记忆条目采用与任务相同的工作区条目卡片模式：卡片展示谓词、对象、主语、来源、置信度和复核次数；点击卡片或“查看详情”打开 `MaterialDialog`。
2. 详情弹窗补充完整三元组、来源、置信度、创建时间、最近复核、复核次数、标签和来源摘录；删除操作保留在卡片操作栏和详情弹窗中。
3. 将条目卡片的几何、状态层、焦点态、底部元信息和操作栏抽为 `app.css` 中的 `.workspace-item-card*` 共享样式。任务页和记忆页只保留各自的内容布局、状态语义和详情字段。
4. 不修改 Tauri 命令、数据库字段、记忆 ID 或持久化格式；新增交互只在前端展示层完成。

## 替代方案

- 继续为记忆维护独立的右侧详情面板：实现改动最小，但与任务的渐进披露模式不一致，且占用固定布局空间。
- 抽取一个带业务字段的通用卡片组件：会把任务和记忆的领域语义耦合在一起，降低独立演进能力；本次只共享视觉外壳和交互几何。

## 影响与验证

记忆页面默认信息密度提高，详情内容从常驻区域改为按需加载的弹窗；任务页面继续保持原有行为，但复用统一卡片外壳。共享 CSS 位于全局设计系统文件中，未引入新依赖或 IPC 变化。

重点验证：

```text
corepack pnpm --dir ui run check
corepack pnpm --dir ui run test:run
corepack pnpm --dir ui run build
```

## 回滚与重置

回滚对应提交即可恢复记忆的右侧详情面板和任务页原有局部卡片样式。无需数据库、配置或缓存重置。
