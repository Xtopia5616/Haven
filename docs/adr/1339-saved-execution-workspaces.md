# ADR 1339：保存执行工作区快捷项

- 状态：Accepted
- 日期：2026-10-20
- 关联：[UI 设计规范](../ui.md)、[执行工作区配置](../release-and-reset.md#当前配置契约)

## 背景

聊天标题区和安全设置都允许选择执行工作区目录，但每次切换都要重新打开系统目录选择器。用户需要保留常用目录，并从聊天标题区直接切换；同时应能移除不再常用的快捷项。

## 决定

1. 聊天标题区提供执行工作区下拉框，包含自动检测、当前配置目录及已保存快捷目录；选择目录仍经 `update_settings` 立即应用并持久化现有 `security.execution_root`。
2. 系统目录选择器仍用于添加目录。聊天标题区选择目录后立即应用 `security.execution_root`，应用成功后再加入本机快捷列表；安全设置页在选中目录时即保存快捷项，`security.execution_root` 仍按设置草稿的保存/放弃流程处理。
3. 快捷列表独立保存在前端 `localStorage`，键为 `haven.execution-workspaces`，不加入 Rust 配置或安全执行边界。最多保存 20 个路径，最近使用的排在最前；路径按 Windows 大小写不敏感方式去重。
4. 下拉框右侧的删除按钮只从快捷列表移除当前路径，不删除磁盘内容，也不更改仍在使用的 `security.execution_root`。用户可通过下拉框切换到另一个目录或自动检测。
5. 本机存储不可用时，当前应用进程中的选择仍可使用；快捷列表不能跨重启保存。没有数据库、配置文件或 IPC 契约变化，无需重置用户数据。

## 替代方案

- 把整个目录列表加入 `config.toml`：拒绝。快捷列表是前端的最近使用便利项，不改变执行策略；独立存储避免把历史路径列表混入安全配置。
- 删除快捷项时同时删除目录或清空当前执行根：拒绝。快捷项删除不应执行文件操作，也不应隐式切换正在生效的设置。

## 验证

- UI 检查覆盖路径保存、重复路径归并、最近使用排序、20 项上限、移除快捷项，以及标题区下拉的鼠标与键盘选择、添加和移除操作。
- 本变更不改变目录 picker 的路径校验和后端 `update_settings` 的执行工作区验证。

## 回滚

移除工作区快捷列表 store 和标题区控件，并恢复目录 picker 入口即可。`localStorage` 中遗留的 `haven.execution-workspaces` 不被运行时读取；无需删除数据库或 `config.toml`。
