# ADR 1165：定义有界声明式 Workflow 图契约

## 状态

已采纳；属于 ADR 1163 的第一条实现切片。同步执行和逐步骤授权已由 ADR 1166 接入；持久化仍未实现。

## 背景

路线图已完成 MCP 暴露策略、嵌套调用授权、可切换 CodeMode，以及用户选择的 Resources/Prompts。下一项是受限 Workflow。需要先固定输入语言和静态验证边界，避免在执行入口建立后再从任意 JSON 或 JavaScript 推导步骤、参数和权限。

## 决定

- Workflow 定义采用严格版本化 DTO；当前只接受 `version: 1`，结构中的未知字段一律拒绝。
- 每个步骤显式引用一个完整 capability name。验证调用方必须提供来自可信的会话目录快照的 capability allowlist；模型输入不能扩充该列表。
- 输入映射只允许 JSON 字面量、显式 object/list 组合，以及指向已有步骤结果的 JSON Pointer。步骤依赖来自 `depends_on` 和结果引用；验证器合并依赖边、拒绝缺失依赖、自依赖和环，并按步骤 ID 的确定顺序生成拓扑执行计划。定义中后置声明的依赖允许由拓扑顺序前移。
- 不支持任意表达式、动态 capability 名、条件分支、循环、并行语义、隐式重试或脚本执行。映射引用的目标字段是否真实存在，在执行前材料化时再次检查；最终参数 schema 仍由每个 capability 现有执行入口验证。
- 默认硬上限为：定义 JSON 64 KiB、16 步、16 层依赖、每步 ID 48 字节、capability name 192 字节、每步 16 条显式依赖、映射 512 个节点/16 层、JSON Pointer 256 字节/16 段、单步输入 16 KiB/全图输入 64 KiB、单步结构化输出 16 KiB/全图输出 64 KiB、最终 observation 32 KiB、执行 90 秒。调用方可以降低上限，不能提高进程上限；同步执行切片必须在每个节点返回时执行输出预算。
- 静态验证只产生 `ValidatedWorkflow` 计划，不执行工具、不签发授权 proof，也不创建权限 grant。每一步运行时仍须经过实时 capability/exposure/target 检查、独立授权和现有 Tools 执行网关。当前切片不引入 ToolRun、数据库状态、配置或 IPC。

## 替代方案

- 把 Workflow 存成 JavaScript 并复用 CodeMode：拒绝；任意控制流、动态路由和解释器语义会扩大静态审计和恢复面。
- 根据步骤名推导依赖或允许任意字符串表达式：拒绝；依赖和数据来源需要在执行前可见、可验证。
- 在验证 Workflow 时一次性批准所有节点：拒绝；验证器不是授权 owner，授权必须按步骤独立完成。
- 此阶段就持久化 Workflow 定义和运行状态：拒绝；当前只实现当前 turn 内的计划，持久恢复与 ToolRun 集成需要独立证明生命周期契约。

## 影响与迁移

新增 `haven-tools::workflow` 版本化类型、静态验证器和结果引用材料化函数，供后续同步执行切片调用。没有数据库、用户配置或 IPC 变更，无需重置数据。模型可见执行工具尚未开放。

## 验证

覆盖版本/字段拒绝、allowlist、依赖闭包、确定性拓扑排序、环、自引用、非法 JSON Pointer、映射复杂度、大小限制及缺失结果引用。
