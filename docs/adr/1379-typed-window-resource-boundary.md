# ADR 1379：窗口与桌面 typed 资源边界

## 状态

已实施 — 2026-10-23。

## 背景

窗口工具已有独立操作视图和风险级别，但授权层没有看到被读取或操作的窗口身份。标题是可变的显示属性，同一标题可匹配多个窗口；仅凭工具名批准会把桌面读取、截图、窗口交互和关闭混成一项能力。

## 决定

1. 窗口 adapter 在授权前解析目标，声明 `window_id`、进程 ID 与访问意图。标题和 PID 仍可作为选择器，但不会被当作授权身份；无法解析或选择不唯一时，在请求确认前拒绝。
2. 窗口访问分为 `read`、`interact`、`close`。桌面范围操作另用 `desktop` 资源，读取窗口列表/前台/等待声明 `read`，截图声明 `capture`；`observe` 同时声明所选窗口读取和桌面截图。
3. UI Automation 交互会在授权前解析具体控件，并将元素 token 的 SHA-256 指纹与窗口身份、`interact` 一起声明。token 原文不写入持久授权范围。执行前重新解析资源；窗口、进程、访问方向或控件指纹任一变化，均拒绝执行。
4. 通过校验后，执行参数会固定到已授权 HWND 和进程 ID；UI Automation 动作进一步固定到已解析的 element token。持久授权范围只匹配完全相同的桌面访问级别，或完全相同的窗口/进程/访问级别/控件指纹。
5. 窗口操作必须由 proof-derived execution context 执行。未声明的操作、缺失 selector、跨平台不可用目标或不匹配的 proof 都 fail closed。工具级风险级别仍用于确定是否需要确认，不替代 typed resource。

## 配置与数据影响

数据库 schema、session event、工具参数和配置默认值不变。配置序列化的 `PermissionResourceScope` 增加 `desktop` 和 `window` 判别分支；旧范围格式不变，无需迁移或重置。IPC 生成联合类型与 Settings 授权说明同步增加新资源描述。

## 替代方案

- 把标题作为持久资源身份：拒绝；标题可变且可重复，无法唯一绑定 HWND。
- 只声明通用 desktop 权限：拒绝；这会把读取、截图、具体窗口交互和关闭合并。
- 将完整 UIA element token 存入设置：拒绝；token 可能包含控件名称且不适合暴露于持久配置，proof 使用其 SHA-256 指纹即可精确比较。

## 验收与限制

测试覆盖桌面读取与截图访问声明、目标缺失时拒绝、执行资源与 proof 不匹配时在副作用前拒绝、窗口授权持久范围绑定 HWND/进程/方向/控件指纹，以及非规范身份拒绝。Windows HWND 是系统运行期身份，PID 绑定用于排除跨进程句柄复用；真实窗口操作和 UI Automation 仍纳入 Windows 发布验收门禁。
