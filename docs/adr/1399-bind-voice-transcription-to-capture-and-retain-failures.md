# ADR 1399：语音转写绑定录音目标并保留可重试源音频

## 状态

已接受；前后端实现与 UI/Rust 自动化门禁已通过（2026-10-25）。真实麦克风、VAD 与隔离 Windows profile 重启验收仍开放。

## 背景

录音结束后 STT 在后台执行。用户可能在 STT 返回前切换会话；当前激活页不能代表开始录音时的目标。此前 STT 失败、应用退出或转写 admission 满时会丢失 WAV，没有可靠重试入口。无界 STT task 也会在快速连续录音下积压。

## 决定

1. 录音开始时冻结当前会话 ID 或 fresh-session 意图及用户选择版本。工具栏先同步目标再启动麦克风；全局热键使用同一递增 revision，迟到写入不能覆盖较新目标。结束与 STT 完成后均以这份快照投递输入。
2. 转写最多同时执行 2 项；超出容量时不排无界任务，而是把源 WAV 保存为唯一 `file-*` 记录并给出重试动作。
3. STT 失败、超时或任务取消时保存 WAV 与目标元数据；上传成功提交用户输入后才删除已保留音频。显式重试复用原文件与目标，不复制一份新录音；同一 retry ID 的并发 IPC 调用幂等为 no-op。
4. 留存最多 10 条、128 MiB 总量、每条 32 MiB；容量满时拒绝新留存但不驱逐旧失败。启动清理由无配对的 WAV/JSON 与 staging 临时文件组成的孤儿，保留完整成对记录。
5. 录音和转写保持麦克风 release 不等待网络操作。timed `media.record` 继续使用其原有输入管线入口。

## 验证

- UI 测试覆盖工具栏先同步 target 再启动录音、会话切换后延迟到达的 voice transcript 仍送入录音原会话、fresh-session 意图不被后来选择改写。
- App 存储测试覆盖失败录音重启后仍可重试、接受提交后可删除、孤儿和 staging 清理、容量上限不驱逐旧项、同文件并发重试去重。
- 仍需在隔离 Windows profile 真实验收：真实麦克风和 VAD 停止；A 转写中开始 B；切换会话；失败后重启并重试；上传提交失败后保留原音频。

## 影响与回滚

没有 schema 迁移。新增的失败音频目录属于用户数据；无需清空数据库或设置。删除功能时必须明确保留/导出已有 WAV 的处置，不能静默删除失败记录。
