# MCP stdio 工作目录授权与启动一致性

## 背景与威胁

宿主进程启动时默认继承进程目录，相对目录也相对进程目录解析；此前授权默认使用执行工作区，可能授权与启动不同的目录。目录不可用、重解析及工作区或策略变更必须拒绝启动。

## 决定

宿主进程启动授权前按当前进程目录解析默认或相对 cwd；WorkspaceWrite 保留执行工作区作为默认目录，通过目录能力验证并固定绝对路径；该路径同时用于资源授权、MXC 策略及宿主进程启动。现有进程边界版本检查与租约继续生效。目录路径替换仍可能发生在验证与启动之间，此改动不声称提供句柄级启动隔离。

## 备选与影响

将默认目录改为执行工作区会改变已有配置语义，故保留进程目录语义。配置及持久数据格式不变，无需重置。回滚可撤销本提交，但会恢复目录授权不一致问题。

## 验证

回归测试覆盖默认、相对和不存在的目录；跨 crate 门禁按开发规范执行。搜索遍历的句柄隔离及失效证明重新授权不属于此切片，仍需独立实现。

## 职责复核

`security/execution.rs` 超过 800 行，目录解析属于现有 MCP 进程授权 owner，进程策略仍位于独立模块；后续测试扩展按进程授权边界拆分。
