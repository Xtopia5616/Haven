# ADR 1121：配置无效回退保持只读直到显式恢复

## 状态

已接受（2026-10-13）

## 背景

`ConfigLoader` 遇到无法解析或未通过语义校验的 `config.toml` 时，会备份原文件并用默认配置继续启动。这让非配置运行能力可以降级工作，但此前 `ConfigService` 仍允许 Settings 读取默认快照、修改配置或暂存凭据。第一次保存会将默认值和本次编辑写回原路径，可能覆盖用户尚未恢复的配置；如果备份也因文件系统错误失败，源文件同样必须保持原样。

## 决定

- Loader 显式记录当前配置是否需要恢复。新建的默认配置和有效配置可写；解析失败或语义校验失败的回退快照仅供 runtime 读取。
- 恢复态下 `ConfigService::settings` 返回包含修复/恢复/重启指引的中文错误，配置更新、底层保存和凭据暂存均拒绝写入；不得生成新的 opaque credential 后留下无引用的凭据。
- 恢复通过用户修复/恢复有效 `config.toml`，或删除该文件后重启完成。重启会重新加载有效配置或创建新的默认配置。无需 schema/IPC DTO 变化，也无需删除数据库。
- 即使原文件自动备份失败，也继续 fail closed 并保留原文件路径不变。

## 替代方案

- 允许 Settings 以默认值加载并继续写入：会把不可见的默认快照写入用户原文件，可能丢失其它有效设置。
- 只阻止配置编辑但允许 Settings 读取为正常状态：界面会误导用户认为当前设置已成功读取，也无法复用既有 Settings 加载失败恢复路径。
- 仅在保存前检查文件指纹：指纹检查不能区分“文件被外部修改”与“本进程已知解析失败并回退”，因此无法阻止基于默认快照的覆盖。

## 影响与验证

- 用户可见行为：损坏或语义无效的配置下，Settings 以既有加载错误路径提示恢复，编辑与凭据录入被拒绝；其它 runtime 仍可使用默认快照启动。
- 持久配置格式、数据库 schema、IPC DTO 与已有有效配置不变；不需要重置数据库。
- Common 单元测试覆盖新建配置、解析失败、语义失败及 ConfigService 的 settings/edit/credential 写入拒绝，并确认原配置文件字节不变。
- 验收使用 `cargo fmt --all -- --check`、`cargo test --workspace --locked`、`cargo check --workspace --locked` 与 `cargo clippy --workspace --locked -- -D warnings`。

## 回滚

回滚时同时移除恢复态写入拒绝、相关测试、本 ADR 和发布/重置说明。回滚会重新允许无效配置回退快照覆盖源文件，不涉及数据库迁移。
