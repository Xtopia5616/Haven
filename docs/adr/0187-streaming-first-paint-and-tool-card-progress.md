# ADR 0187：首字节直达与工具卡片增量进度

## 状态

已接受（2026-09-20）

## 背景

LLM chunk 在 provider、Agent batcher、Tauri 事件和 UI RAF 之间连续经过多层
调度。首个可见 chunk 如果每层都等待下一次调度，会在文字开始、工具卡片出现和
工具输出到达之间形成短暂空白。前台工具输出还复用了后台任务的较长刷新间隔，
使工具卡片看起来像是等工具结束后一次性补齐。

## 决定

1. LLM 流的首个可见文本/推理 chunk 在有限首包窗口内直达已有回调；后续 chunk
   继续走有界队列，保留容量上限与取消语义。
2. UI 对每个 session/step/run 的首个可见 chunk 立即绘制；同一流的后续 chunk
   继续按 RAF 合并。立即绘制前取消旧 RAF，避免跨流的旧回调抢先消费新流内容。
3. 前台工具输出使用 100–250ms 的有界刷新 cadence，并在轮询开始时先检查一次
   已有尾部内容；工具卡片仍以 `agent:observation` 的权威结果完成收口。
4. 工具实时尾部依旧是 UI-only、有界的预览，不写入 transcript 或数据库；最终
   observation 仍是恢复、复制和历史展示的唯一内容来源。

## 替代方案

- 取消所有 batch：会显著增加 IPC、渲染和 Tauri 事件压力，拒绝。
- 把每个实时尾部 tick 写入 SessionReducer：会重建整条时间线并重新挂载历史卡片，
  拒绝。
- 让实时预览替代 observation：会把不完整尾部变成持久化真相，破坏恢复契约，拒绝。

## 影响、验证与回滚

这项变更只调整流式调度和 UI-only 工具预览的时序，不改变 Tauri payload、数据库
schema 或工具结果格式。验证包括 LLM workspace 测试、工具实时输出测试、UI
stream aggregator 测试、前端检查与完整前端测试。回滚对应代码即可，无需重置数据。
