# 0125：UI 全局文字选择与右键回退菜单

## 背景

Haven 的文字选择和右键菜单过去主要由聊天气泡、工具卡片、会话卡片和输入框分别实现。没有专属交互的工作区文字缺少一致的右键入口；部分可读内容还被交互容器的 `user-select: none` 一并覆盖。

## 决定

- 在全局基线明确可读文字使用 `user-select: text`，保留按钮、Tab、输入控件和拖拽滚动表面的局部交互隔离。
- JSON 树节点和可展开资源卡片标题属于可读内容，允许选择；它们仍保留展开和键盘交互。
- 在 `AppShell` 挂载唯一的全局菜单宿主，并通过 `contextMenu.ts` 提供统一的菜单状态和 `openContextMenu(event, items)` / `openContextMenuAt(x, y, items)` API。业务区域只需提交菜单项和动作，因此菜单可以包含复制以外的任意操作；已有组件通过 `stopPropagation()` 保持自己的菜单和动作。
- 在同一宿主上保留文档冒泡阶段的右键回退处理器：只有事件未被领域组件处理、目标不是编辑控件且存在选中文字时，才阻止原生菜单并提供“复制选中内容”。
- 没有文字选中时不拦截原生行为，避免破坏表单编辑和系统自带的输入菜单。

## 替代方案

- 让每个页面继续自行添加菜单：会继续产生覆盖遗漏和交互漂移。
- 在捕获阶段强制接管所有 `contextmenu`：会抢先覆盖已有领域菜单，也会破坏输入控件的编辑菜单。

## 影响

普通工作区文字可以统一选中；在未提供专属菜单的文字区域选中内容后右键，可以复制选中内容。已有业务区域和后续区域可以复用全局宿主并注册复制以外的自定义动作。控件和拖拽滚动仍按原有交互运行。该变更不涉及持久化、IPC 或数据重置。

## 验证

- `cd ui; corepack pnpm run check`
- `cd ui; corepack pnpm run test:run`
- `cd ui; corepack pnpm run build`

## 回滚

删除 `GlobalContextMenu` 的挂载、`contextMenu.ts` 以及调用点，并恢复本 ADR 涉及的选择样式；无需数据迁移或重置。
