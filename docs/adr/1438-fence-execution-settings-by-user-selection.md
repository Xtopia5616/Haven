# ADR 1438：会话执行设置按发起时选择隔离

## 状态

已实施 — 2026-10-27。

## 背景与证据

R12 源码复核发现，聊天页 `persistExecutionWorkspace` 与 `selectExecutionMode` 在 IPC 返回后直接更新当前展示。用户在等待期间从 A 切到 B 或新草稿，A 的结果便会覆盖新选择的执行设置。`addExecutionWorkspace` 还在目录选择器返回后才读取活动会话，可能将原本为 A 选择的目录写入 B。原有读取请求序号只隔离读取之间的竞争，不能阻止保存前的读取覆盖保存结果。

## 决定与不变量

- 在用户发起动作时捕获 session ID 与用户选择版本；已发出的保存继续绑定原目标，展示更新与成功通知要求原选择仍有效。
- 目录选择器返回时若用户选择已变化，取消后续保存；切走再切回同一会话也属于新选择。
- 新草稿的设置保存更新默认配置快照；只有原选择仍有效时才更新当前展示。
- 保存使该字段先前读取失效，避免旧读取覆盖新设置；目录和执行方式分别维护既有读取顺序。
- 继续沿用每类动作的现有等待准入，不增加后台任务、持久影子配置或新的授权入口。

## 替代方案与范围

仅比较 session ID 无法识别切走再切回或两次新草稿选择；仅在保存响应后丢弃结果不能防止选择器错写新会话。选择版本复用现有会话动作 owner，设置操作协调留在 UI 内部，后端仍负责实际授权与配置写入。

聊天页已超过职责复核阈值，本切片将执行设置动作归入独立 controller，页面保留展示与现有读取生命周期；不扩大通用 SessionReducer 的职责。

## 影响、回滚与重置

仅 UI 内部协调变化，Rust、IPC shape、数据库、配置格式和持久事件均不变，无需数据重置。回滚 controller、页面接线与回归测试会重新引入上述竞态。

## 验证

- 旧逻辑的四项回归均先失败：目录保存迟到、切走再切回后的方式保存迟到、选择器错投与默认目录污染新选择。
- 8 项定向回归复用真实 SessionReducer 的选择版本，覆盖成功、失败、取消、默认配置与规范化返回值。
- Node 24.21.0、pnpm 12.12.1：Svelte check 为 0 errors、0 warnings；UI 全量 171 文件、1547 项测试通过；生产构建及 CSP manifest 生成通过。测试运行有 TimeoutNaNWarning，退出码为 0。
- 受影响 UI Prettier、ADR index（1335 条）及 diff 检查通过。仅 UI 内部变化，未重跑 Rust 门禁；真实 WebView 交互仍归路线图 §5.1，未生成发布包。
