# ADR 1137：不在诊断与配置 Debug 输出中暴露敏感值

## 背景

错误文案曾包含无法打开的本机路径；录音静音日志和 capture callback 诊断包含样本振幅。Common 配置类型派生或实现的 `Debug` 还可能输出命令、参数、工作目录、URL path/query、代理例外或认证 header 前缀。路径净化器不能覆盖所有平台路径形式，而运行时幅值和配置细节也不是排障所需的稳定摘要。

## 决定

- 外部启动命令的 missing-path 错误改用固定文案，不回显路径。
- 静音采集日志只报告稳定失败类别；callback 诊断保留回调计数与是否观察到非静音信号，不输出 RMS/peak 数值。
- 配置与连接类型的 Debug 输出将命令、参数、cwd、完整 URL、`no_proxy` 项和 auth header 前缀替换为固定占位符，同时保留安全的配置身份与状态字段。
- 更新 `docs/conventions.md`，明确 Debug 输出也按日志内容处理；敏感字段的测试使用哨兵值检查不会泄漏。

## 替代方案

- 依赖通用路径/错误清洗器：拒绝。清洗器无法对任意 POSIX 路径、配置内容和运行时采样值作完整识别。
- 保留振幅但标成结构化字段：拒绝。该数值不是当前诊断所需的分类或稳定实体身份。
- 删除配置类型的 Debug：拒绝。保留调试可用性，以字段级占位符限制输出。

## 影响与验证

用户可见 missing-path 错误保持为文件不存在类别；capture 行为不变，仅日志诊断更少。配置序列化、运行时行为、IPC 和持久化格式均不变，不需要重置。验证覆盖路径不泄漏、采样诊断不包含峰值值，以及配置 Debug 哨兵不泄漏；运行 Common、Input、App Binary 相关测试与 workspace 门禁。

## 回滚

没有持久数据或配置格式变化。回滚只需恢复安全格式化字段及固定错误/日志描述；不得恢复原始敏感值输出。
