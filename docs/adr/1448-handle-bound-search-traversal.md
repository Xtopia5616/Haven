# ADR 1448：搜索使用句柄相对遍历

## 背景与威胁

ADR 1445 的路径过滤发生在第三方遍历器访问目录和规则文件之后；攻击者可以替换路径，规则文件也可能位于显式禁止范围。搜索结果不能作为授权来源，Everything 的索引同样不提供文件访问授权。

## 决定

原生搜索和 Everything 结果过滤共用有界遍历器。根目录和每级子目录由持有的目录句柄打开；子项以单个名称相对打开，明确禁止跟随符号链接和重解析点，读取前以已打开对象验证文件读取策略。Windows 目录句柄不共享删除，阻止遍历期间替换目录。内容搜索和行范围搜索消费已验证的文件句柄，不重新按路径读取。规则文件也通过同一目录句柄打开并授权，失败记入不完整结果。

规则范围为搜索根内的 `.ignore`、`.gitignore` 和目录型 `.git/info/exclude`；不再自动读取搜索根以外的父级规则、Git 全局配置或外部 worktree 的 gitdir。目录型 `.git` 以外的 gitdir 无法安全解释时报告不完整。此调整避免隐式读取未授权位置；调用方若需要这些规则，应将它们放在授权搜索树内。规则文件单个上限 1 MiB，累计预算 4 MiB（每个目录最多预读三个文件），有效规则文件最多 1024；遍历最多 100000 项、待处理目录最多 1024，达到上限报告截断。目录枚举及内容读取支持取消。Everything 的候选必须在相同遍历中被确认，扫描在阻塞线程执行且保持并发许可。

不保留路径 walker 作为降级方案：它不能约束内部规则读取，也无法把路径检查和后续遍历绑定到同一对象。新依赖 `cap-fs-ext` 提供现有 cap-std 打开选项的显式 no-follow 接口，避免自行实现 Windows FFI。

## 验证与影响

回归覆盖被禁止的规则文件、普通规则及仓库 exclude、深度和条目上限、文件内容与行范围读取，以及 Windows 子目录句柄阻止替换、重解析点拒绝。Windows junction 拒绝测试已通过；本机没有创建普通符号链接的权限，该部分测试跳过，仍需在可创建符号链接的环境验证。搜索现在逐目录串行遍历，可能比旧并行 walker 慢；Everything 过滤也需要扫描搜索树并受相同预算约束。没有数据库或持久化契约变化，无需重置；回滚需同时回滚平台句柄接口和两个搜索入口。
