# ADR 0096：幂等启动开发服务器

## 背景

桌面开发由 `cargo tauri dev` 启动 Rust/Tauri 后端，并通过 `beforeDevCommand` 启动
Vite；浏览器预览也使用同一个 `4721` 端口。先打开浏览器预览、再启动桌面开发时，
两个入口会尝试创建第二个 Vite 进程，`strictPort` 随后报告端口已占用。浏览器预览本身
没有 Tauri IPC，容易被误认为是后端启动失败。

## 决定

- `ui` 的 `dev` 入口经过 `scripts/dev-vite.mjs`。它先检查 `4721` 上是否已经是
  当前 Haven 的 Vite 开发服务器；是则复用并保持入口进程存活。
- `4721` 被其它服务占用时立即失败，并说明端口冲突，不自动杀掉未知进程。
- 浏览器预览继续保持无后端语义，但状态按钮明确显示“浏览器预览”及启动桌面应用的
  提示；完整功能必须使用 `cargo tauri dev` 或根目录 `pnpm run dev`。
- `cargo tauri build` 仍只执行静态 UI 构建，不依赖或复用开发服务器。

## 替代方案

- 让 Vite 自动换端口：Tauri 的 `devUrl` 和开发 CSP 使用固定端口，自动换端口会让
  Tauri 连接到错误的页面。
- 自动终止占用端口的进程：无法安全区分用户的其它服务，且会扩大开发脚本的破坏性。

## 影响、验证与回滚

本决定只改变开发进程管理和浏览器预览提示，不改变 Rust IPC、数据库、配置或生产构建。
验证包括 UI 检查、组件测试、生产构建，以及先运行 UI dev 再运行 Tauri dev 时不产生第二个
Vite 进程。回滚脚本、UI 入口、提示和本 ADR 即可。
