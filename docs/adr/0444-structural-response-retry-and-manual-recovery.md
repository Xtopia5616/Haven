# ADR 0444：结构化工具参数重试与手动恢复

## 背景

ReAct 对话会在模型回复结尾匹配若干词语、标点，或收到非 `Stop` 结束原因时自动重试，并会替换正在显示的输出。空响应也有独立的自动重试。文本尾缀无法可靠判断回答是否完整；不同 provider 的结束原因也不都代表可安全自动续写。这些重试会让已显示内容消失或被另一版回复覆盖。

## 决定

1. 只对非最终工具调用中明确无法解析的参数 JSON 自动重试；重试要求模型重新输出完整参数，不续写半截 JSON。默认最多两次，可在设置中调整。
2. 参数仍不完整、重试不可执行或重试失败时，将会话置为可恢复错误，保留已生成的部分内容并显示“继续生成”。不把空参数交给工具执行。
3. 删除文本结尾词/标点判断以及空响应自动重试。`finish_reason` 不是正常终止时也走可恢复错误；完整工具调用的 `tool_calls` / `function_call` 终止仍按正常工具响应处理。
4. 空响应走可恢复错误，不触发自动重试。正常 `Stop` 下已有未回答 Ask 时仍按 Ask 生命周期暂停。
5. 删除旧的 `cut_off_retries`、`empty_response_max_retries` 和 `empty_response_retry_delay_ms` 配置项，统一为 `incomplete_tool_args_retries`。配置采用当前结构且拒绝未知字段，所以旧 `config.toml` 会按既有策略备份并回退默认配置；需要重建配置文件，不涉及数据库或会话数据重置。

## 替代方案

- 保留文本尾缀猜测：拒绝，词语和标点不是回答完整性的可靠证据。
- 对所有非 `Stop` 响应自动续写：拒绝，内容过滤、未知原因和协议错误不能安全地当成续写请求。
- 超出结构重试预算后继续执行工具：拒绝，空参数或 schema 占位符可能造成非预期副作用。

## 影响与回滚

一般文本输出不会因末尾措辞触发自动重置；模型非正常结束和空响应会显示错误及“继续生成”。完整工具调用仍正常执行，明确不完整的参数仍有有限自动重试。回滚时恢复旧代码与配置结构；旧版配置备份可供检查，但当前配置契约不提供字段迁移。

## 验证

覆盖文本尾缀不触发重试、非正常结束转为错误、不完整参数不进入工具执行且重试后只执行完整调用、预算耗尽后错误、空响应不自动重试，以及旧配置键拒绝。运行 Rust workspace 与 UI 检查、测试和构建，并检查 IPC 合约。
