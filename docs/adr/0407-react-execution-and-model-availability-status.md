# ADR 0407：ReAct 执行阶段与模型可用性分开展示

- 状态：已采纳
- 日期：2026-09-29

## 背景

标题栏此前把 ReAct 执行阶段、会话等待原因和默认模型连接状态压成一个状态文案。执行中时连接状态被遮住；轮询超时还可能把仍在运行的阶段提前重置为空闲。

## 决定

- 标题栏将执行阶段与模型状态作为独立状态展示。
- 执行阶段使用 `idle`、`queued`、`requesting`、`generating`、`waiting_result` 和 `waiting_response`；阶段只由生命周期、Agent 流、工具结果或会话终态事件推进，不靠短时 idle timer 推断结束。
- 用户输入、ask、普通确认和定时任务确认统一显示“等待操作”；后台任务等待显示“等待任务”。“请求中”“生成中”“等待响应”“等待结果”分别表达模型请求、模型输出、流停滞和工具执行等待。
- 模型状态只显示“未配置”“检测中”或不可用时的“网络错误”。连接正常时不额外显示成功文案；错误详情保留在悬浮提示中。
- 本次复用现有会话和 Agent 事件，不新增持久化、Tauri 事件或命令契约。

## 替代方案

- 继续使用单一状态文案：执行阶段会继续遮住模型可用性。
- 仅用计时器推断阶段：长请求或流间隔可能被误报为空闲。
- 为每个显示阶段新增后端事件：目前现有事件足以表达本次需要的阶段，新增 wire 契约没有必要。

## 影响

设置状态文案、状态投影和相关 UI 测试；对数据库、配置文件、IPC 与用户数据无影响。健康探测结果表示默认模型最近一次探测情况，不保证任意单次请求一定成功。

## 验证

- `corepack pnpm run check`
- `corepack pnpm run test:run`
- `corepack pnpm run build`

## 回滚与重置

回滚前端状态展示与投影改动即可；无需数据库或配置重置。
