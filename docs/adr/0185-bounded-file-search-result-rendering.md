# ADR 0185：文件搜索结果分批渲染

## 状态

已接受（2026-09-20）

## 背景

文件搜索的后端结果上限是 1,000 条，但 UI 之前会在结果卡片展开时为所有结果
同步创建 `ExternalRef` 和行节点。宽目录或内容搜索即使很快完成，也可能让 WebView
主线程长时间忙于 DOM 更新，期间折叠、停止输出和结束会话只能显示点击反馈而不能
及时执行；这不要求对话很长即可触发。

## 决定

1. 文件搜索结果首屏最多渲染 15 条。
2. 通过现有 `MaterialButton` 按 15 条递增显示，保留查看已返回结果的能力，同时
   避免一次性把后端上限全部挂载到 DOM。
3. 结果总数继续使用后端 `count` 展示；分页只限制 UI 节点数量，不改变工具输出、
   模型上下文或复制结果。

## 替代方案

- 继续一次性渲染全部结果：实现简单，但会重复触发 WebView 主线程卡顿，拒绝。
- 只在后端降低 `max_results`：会改变模型可见搜索结果和工具契约，不能单独解决 UI
  渲染成本，拒绝。
- 引入虚拟列表依赖：当前结果卡片已有分批交互，新增依赖和复杂度没有必要，暂缓。

## 影响、验证与回滚

搜索结果默认只显示首批，用户可按需继续展开；工具输出结构、搜索参数和后端行为
不变。验证包括 250 条结果的 DOM 上限与分页回归测试、前端检查和前端测试。回滚
代码即可。
