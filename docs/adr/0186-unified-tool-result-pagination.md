# ADR 0186：工具结果统一分批渲染

## 状态

已接受（2026-09-20）

## 背景

文件搜索暴露了一个不只属于单个工具的问题：多个工具 renderer 和通用 `JsonView`
会在结果卡片展开时直接把数组全部挂载到 WebView DOM。后端虽然通常有结果上限，
但目录、网页引用、窗口元素、环境变量和任意 JSON 数组仍可能一次产生数十到上千个
节点，阻塞主线程并让工具卡片和会话控制失去响应。

## 决定

1. 所有工具结果数组和 `JsonView` 展开的数组统一使用 `ToolResultList`。
2. 首屏最多渲染 15 项；“显示更多”每次追加 15 项。
3. 分页只限制 UI DOM 挂载数量，不修改工具输出、模型上下文、复制 JSON 或后端结果
   上限；ask 选项等有独立小上限的交互控件不套用结果分页。

## 替代方案

- 只给文件搜索加特殊逻辑：会把同一类卡顿留给网页搜索、目录列表和通用 JSON，拒绝。
- 只依赖 `max-height: overflow-y: auto`：只能限制可视高度，不能减少 DOM 创建，拒绝。
- 引入虚拟列表依赖：当前固定分页已满足首屏响应性，新增依赖和复杂度暂缓。

## 影响、验证与回滚

工具结果卡片默认更紧凑，用户可按需继续查看结果；分页按钮和文案在所有结果列表
保持一致。验证包括文件搜索、进程和通用 JSON 数组的分页回归测试、前端检查、完整
前端测试和生产构建。回滚代码即可。
