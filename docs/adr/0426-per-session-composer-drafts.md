# ADR 0426：按会话缓存输入框草稿

- 状态：Accepted
- 日期：2026-10-02
- 关联：ADR 0313、0322

## 背景

聊天输入框只有一份文本状态。切换到另一会话后，未发送的文本会继续显示在那里，容易把草稿误发到错误的会话；切回原会话时也无法恢复草稿。

## 决定

1. Composer 按当前会话 ID 缓存未发送的文本草稿；新会话使用独立的 `_draft` 槽位。
2. 草稿只在 Composer 挂载期间保留于前端内存。成功提交时清除当前槽位；切换会话时保存离开的草稿并恢复目标会话草稿。
3. 缓存最多保留 100 份已离开的非空草稿，按最近访问顺序淘汰最旧项。附件不进入草稿缓存，保持现有行为。
4. 不写入 localStorage、数据库或 transcript，也不新增 IPC；因此草稿不会在应用重启后恢复。

## 替代方案

- 持久化到 localStorage 可跨重启恢复，但会额外长期保存用户尚未发送的私密文本，超出本次会话切换需求。
- 将草稿写入 transcript 或数据库会混淆未发送内容与正式对话历史，并引入恢复和清理契约。

## 影响与重置

只改动 UI 内存状态，无数据库、配置、事件或 Tauri wire 契约变化，无需重置数据。关闭聊天页面或重启应用会丢弃缓存草稿。

## 验证

需覆盖 A/B 会话切换后的草稿隔离与恢复、提交后清理、新会话独立槽位及超过 100 份时淘汰最旧草稿。此次变更未执行 UI 自动化门禁。
