# ADR 1140：对配置写入与外部变更检查复用文件上限

## 背景

配置加载对 `config.toml` 实施 4 MiB 有界读取，但保存会无界写临时文件，外部修改检测则用无界 `std::fs::read` 计算指纹。有效 Settings 可能因此写入重启后无法加载的文件；外部替换的大文件也会触发无界分配。

## 决定

- 序列化后的 TOML 在创建临时文件前不得超过 `MAX_CONFIG_FILE_BYTES`；超限拒绝更新。
- 外部源指纹通过同一有界读取 helper 获取；源文件超限时清理临时文件并 fail closed，不覆盖外部文件。
- ConfigService 更新失败时保留当前快照、版本和源文件；重置文档说明 4 MiB 的拒绝与恢复语义。

## 影响与验证

配置格式和 4 MiB 读取上限不变。超限 Settings 不写盘；外部超限源文件保持不变，不自动备份或回退默认值。缩小文件并重启即可，无需重置数据库。回归覆盖序列化超限、外部源超限以及 ConfigService 快照/版本/文件保持不变；验证 Common locked tests、严格 Clippy 和格式检查。

## 回滚

不得恢复无界写入或外部 fingerprint 读取。若调整预算，读取、持久化、恢复文档与相应边界测试必须使用同一个明确硬上限。
