# ADR 0451：有界并发读取 Skill 子进程输出

- 状态：Implemented
- 日期：2026-10-04
- 范围：`SkillRunner` 的子进程输入、stdout/stderr 读取与退出等待
- 关联：ADR 0002、0060、0086

## 背景

`SkillRunner` 先写 stdin 并等待子进程退出，之后才读取 stdout 和 stderr。子进程写满任一 OS 管道时会阻塞，父进程则一直等它退出，最终误报超时。旧路径还将完整 stdout/stderr 读入内存，再按行数截断，因此技能可以用无界输出耗尽内存。后台 shell 已有“并行排空并丢弃超额字节”的实现，但 Skill 未复用该边界。

## 决定

1. stdin 写入、stdout/stderr 排空和子进程 wait 在同一超时/取消边界中并发推进。
2. 两个输出流各自最多保留 8 MiB；达到上限后继续读取并丢弃多余数据，避免关闭管道造成子进程写失败。
3. 任一流超过字节上限，或输出超过既有行数上限时，Skill 返回明确失败和有界诊断预览，不尝试解析截断后的 JSON。
4. 复用 Tools 的有界读取原语。超时和取消通过销毁 Tokio child 与 Job Object containment guard 清理子进程树；不遗留 detached reader。

## 影响

超过限制的技能输出现在确定性失败，避免无界内存消耗；正常输出、stdin JSON 格式、UTF-8/本地代码页解码、stderr 错误映射、进程隔离及超时/取消结果保持不变。数据库、配置、IPC、provider wire 和用户数据不变，无需重置。

## 验证

覆盖读端保留字节上限后仍将管道排空，以及两个输出流同时超过上限时进程仍能完成并返回明确失败；超时测试使用临时 venv/work 目录并断言具体超时结果。运行 Tools 定向测试与 workspace 质量门禁。

## 回滚

如需临时恢复旧 Skill 输出行为，应同步恢复有界读取前的并发 wait 实现；不应单独恢复“wait 后读取”，否则会重新引入管道死锁。恢复无界读取前须重新定义并验证进程输出容量策略。
