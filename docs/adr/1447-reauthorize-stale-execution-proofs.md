# ADR 1447：失效执行证明重新进入授权门禁

## 背景与威胁

工具重试前证明可能过期，或策略、工作区、会话执行模式已经变化。旧证明不得沿用；重新评估也不能允许证明转用于另一会话、工具、能力、输入或目标。

## 决定

执行前识别上述失效条件，对同一调用重新解析当前资源并进入现有授权门禁。门禁可自动批准、要求新的用户确认或拒绝；取消、交互失败及重新验证失败都拒绝执行。证明另绑定原始输入摘要，以区分工作区变化导致的资源变化和输入替换。目标身份变化继续拒绝；同一能力的子调用仍需独立证明。并发变化在重新批准后发生时继续 fail closed，不无限重试。

## 影响与替代方案

不复用旧确认，避免策略变化后沿用不再有效的授权；仅返回失败则不能恢复过期证明。证明是进程内数据，不改变持久化或 IPC 契约，无需重置。回滚将恢复旧证明失效后直接失败的行为。

## 验证

回归覆盖过期、策略变化、输入和目标不匹配；需运行工具执行及工作区门禁。搜索遍历与忽略文件的句柄级隔离是独立的未完成工作。

## 职责复核

`security/engine.rs` 超过 800 行，授权判断继续保留在唯一策略 owner；本次新增的测试验证该 owner 的证明边界。后续测试扩展应按证明生命周期拆分测试模块。
