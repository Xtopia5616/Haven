# ADR 1097：限制 ConfigService 变更通知积压

## 状态

已接受（2026-10-13）

## 背景

`ConfigService::subscribe` 为每个订阅者创建无界 mpsc 队列。持有 receiver 却不读取的调用方会让每次成功配置变更持续占用内存。通知只用于提示哪些 domain/version 已变更，配置快照才是权威状态；当前生产路径没有订阅者，调用仅见于测试。

## 决定

- 每个订阅者使用容量为 64 的同步有界队列；发布通过非阻塞 `try_send`。
- 队列已满或 receiver 已关闭时，从发布列表移除该订阅者；它可以读完已排队通知后观察断开，重新订阅并从 snapshot 刷新权威配置。
- 配置持久化和变更响应不依赖通知送达；通知不得作为配置状态的唯一来源。

## 影响

单个慢消费者最多积压 64 条 `ConfigChanged`。超限时该消费者显式断开，配置更新仍正常提交；未来生产消费者必须处理断开、重新订阅并读取 snapshot。

## 验证

Common 单测验证慢订阅者在容量满时断开、已排队事件仍可读取，重新订阅后可收到更新；app-binary Settings 测试覆盖现有订阅 API。

## 回滚

不得恢复无界 mpsc。若改用可合并通知，应继续保证消费者能从权威 snapshot 重建状态且发布端不阻塞。
