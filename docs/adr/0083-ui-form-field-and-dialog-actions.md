# ADR 0083：UI 表单字段与弹窗操作原语

## 背景

MCP 编辑弹窗重复实现了表单字段的标签、纵向间距和校验错误布局；多个通用弹窗也重复书写相同的 `md-btn` footer 按钮。输入控件本身仍然需要由各业务组件决定，但这些布局和动作外壳应有唯一实现，避免后续页面间距、错误文案样式和按钮行为发生漂移。

## 决定

- 新增无业务状态的 `MaterialField`，统一字段标签、关联控件 id、辅助文本、错误文本和字段间距。
- MCP 编辑弹窗使用 `MaterialField` 包裹文本输入、文本域和选择器；控件绑定、校验和字段语义继续由弹窗持有。
- API Key、回退确认、MCP 编辑和日期选择器弹窗的常规 footer 操作使用 `MaterialButton`；日期选择器内部的日期格、翻页和年份按钮仍保留专用视觉与交互。
- 不把所有原生输入或所有按钮强行抽象为一个组件：特殊行为（如密钥字段、数字步进器、日历导航和安全确认）继续由领域组件实现。

## 替代方案

- 只复用全局 CSS：无法统一字段结构和错误消息的语义，也容易继续复制 DOM。
- 让 `MaterialField` 负责输入值和校验：会把业务状态带入展示原语，违反 `lib/` 组件的纯展示边界。
- 将所有按钮都替换成 `MaterialButton`：会覆盖图标按钮、日历控件和危险确认等行为不同的按钮，降低可读性并增加误改风险。

## 影响与回滚

本次只改变前端组件组合和重复样式的来源，不改变 IPC、表单数据、校验规则、弹窗生命周期或用户数据，不需要重置。回滚本提交即可恢复迁移前的字段和 footer 实现。

## 验证

- `cd ui; corepack pnpm run check`
- `cd ui; corepack pnpm run test:run`
- `cd ui; corepack pnpm run build`
