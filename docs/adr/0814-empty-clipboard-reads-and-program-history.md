# ADR 0814：空剪贴板读取与程序写入历史

## 状态

已接受（2026-10-08）

## 背景

Windows 空剪贴板读取文本时，`arboard` 将缺少 `CF_UNICODETEXT` 映射为 `ContentNotAvailable`；`clipboard.read` 的 `auto` 分支继续探测文件列表时，`GetClipboardData(CF_HDROP)` 则可能返回系统错误 1168。两条路径都把“没有可读内容”暴露成工具失败。

ClipboardTool 已共享进程级 `ClipboardHistory`，并在成功的文本写入、读取和 history 查询采样时记录文本。但文本读取与 history 查询使用不同的代码入口，缺少程序写入后通过文本读取进入同一历史的回归覆盖。

## 决定

- 显式文本读取把 `arboard::Error::ContentNotAvailable` 归一化为空字符串；其它错误仍然失败。
- `auto` 仍优先返回可读文本、HTML、图片或文件列表；只有最终文件列表探测返回 Windows `ERROR_NOT_FOUND`（1168）时才返回空文本，其它错误原样传播。
- 文本读取和写入共用可注入的文本边界；成功的 Haven 文本写入与读取都继续进入同一个进程级历史。空字符串不作为历史条目。

## 影响与取舍

- `clipboard.read` 对空剪贴板返回成功的空文本结果，不改变非空内容的输出结构。
- 历史仍是进程内有界状态；不增加系统剪贴板监听、持久化、数据库迁移或重置要求。
- 将格式缺失视作空文本符合读取调用的预期；剪贴板占用、转换失败等错误仍能提示真实故障。

## 验证

- 单测覆盖缺失文本格式返回空值、Windows 文件格式 1168 被限定归为空值、其它系统错误不被吞掉。
- 注入文本读写边界，回归验证程序写入后读取并查询 history 可见一条内容且不会因重复读取产生重复项。
- 在 Windows 上验证真实空剪贴板的 `clipboard.read` 与 `auto` 行为。

## 回滚

无持久数据变化。回滚只恢复工具错误语义；无需清理数据库或配置。
