# ADR 0429：剪贴板写入使用显式格式和载荷

- 状态：Accepted
- 日期：2026-10-03
- 关联：ADR 0137、ADR 0213

## 背景

剪贴板写入此前允许省略格式，并用 `content`、`html` 的组合推断意图。HTML 写入还会把
`content` 当作纯文本回退值，模型难以判断它是主载荷还是辅助值；格式和字段冲突时，执行器
可能忽略多余字段。

## 决定

1. 每次写入都必须显式指定 `format`，仅接受 `text`、`html`、`image`、`files`。
2. 对应载荷分别使用 `text`、`html`、`asset_id`、`files`。HTML 可以附带可选 `text`，语义
   固定为纯文本回退值。
3. Schema 和执行时校验都拒绝缺少格式、自动格式以及与格式不匹配的字段；旧 `content` 写入
   字段不再接受。
4. 剪贴板读取结果中的 `content` 保持不变，它仍表示读取到的文本。

## 替代方案

- 保留无格式写入并通过字段存在性猜测格式，会继续保留原歧义。
- 将 HTML 回退文本完全删除会收窄功能；命名为 `text` 并限定其角色更清楚。

## 影响与重置

这是模型可见的内置工具参数契约变更，不涉及数据库、配置或权限语义，无需重置用户数据。
已加载旧 schema 的当前模型调用需要按新 schema 重试。

## 验证

覆盖格式分支、必需载荷、旧字段和冲突载荷；运行 `haven-tools` 测试及项目规定的后端门禁。
