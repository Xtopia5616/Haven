# ADR 1445：搜索和 MCP 子进程使用已批准的读取范围

## 背景

文件搜索先前重新读取默认策略，导致范围扩展获批后内容搜索和 Everything 仍可能拒绝；普通文件名遍历则没有按读取策略过滤条目。MCP 的工作目录限制在进程策略中执行，授权评估未识别工作区外工作目录需要范围扩展。

## 决定

搜索使用执行证明派生的读取策略；先检查根目录，再在普通搜索的遍历中按该策略过滤文件和子目录。Everything 的进程策略绑定具体读取资源，并保持只读根和显式拒绝。MCP 的工作区外工作目录在授权评估时触发范围扩展申请；进程策略将实际目录与证明的读取资源匹配。显式拒绝保持优先。拒绝或取消不产生执行证明。

## 风险与替代方案

目录遍历依赖操作系统路径和第三方 ignore walker；检查与随后的遍历之间仍有路径变更竞态，不能把它当作句柄相对隔离。ignore walker 自行读取忽略规则文件，单独的文件拒绝对这些内部读取的约束仍需后续设计；本变更不声称解决这一问题。进程策略的范围不能仅由一个泛化的范围扩展布尔值授权。保留原默认读取策略会使已批准请求失败。

## 验证与回滚

回归测试覆盖确认后的内容搜索、禁止文件和目录、Everything 的已批准根，以及 MCP 工作区外目录确认后的策略和不匹配目录拒绝。Windows MXC 实际启动仍需依赖运行环境进行验收。回滚恢复原范围行为；没有持久化契约变更，无需数据重置。

## 职责复核

`security/execution.rs` 超过 800 行，本次增长以授权边界回归测试为主；进程策略仍由独立的 `process_policy` 模块负责。后续扩充测试时应按稳定的授权边界拆分测试模块。
