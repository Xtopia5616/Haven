# ADR 1414：网络开关与域名约束共用运行时策略快照

## 状态

已采纳。

## 背景

全局网络策略与域名范围同属 `NetworkResourcePolicy`，但 Tools 授权运行态把它们拆成 `network_policy` 和 `global_network_domains` 两个独立字段。配置应用、策略修订、进程边界失效和授权判断需要分别同步这两份数据，容易在切换网络模式时丢失或错配域名约束。

## 决定

- Tools 授权运行态直接持有一个全局 `NetworkResourcePolicy`，访问模式和域名列表随同一份配置快照更新、比较和失效。
- `access` 与 `allowed_domains` 保持两个独立字段：`deny` 仍会拒绝联网，即使配置了域名；域名列表只收窄可访问目标，不会开启网络。全局与工具级列表同时存在时取交集。
- 各执行入口继续按其可验证能力执行策略。域名约束不被当作 Shell、浏览器或其它 opaque 子进程的网络代理；受限网络继续只允许可验证的公共目标，拒绝回环、私有网段及特殊用途地址。
- Web 搜索、浏览器、MCP 和 Shell 的执行授权与网络隔离仍属于各自入口；此重构只合并 Tools 内部的全局策略快照，不增加跨入口的万能开关。

## 影响与迁移

仅改变进程内授权策略的持有方式和 Settings 安全说明，不改配置、IPC、数据库或网络执行语义，无需重置数据。重启后仍从原有 `resource_policy.network` 配置加载。

## 验证

- Rust 测试验证切换网络访问模式不会清除域名范围。
- UI 测试验证域名列表不能开启网络，并明确受限网络拒绝本机与私有地址。
- 运行受影响 Rust crate 与 UI 的适用门禁。

## 回滚

恢复授权运行态中的独立标量字段，并移除其策略映射；保留原有配置格式。还原 UI 说明与本 ADR，无持久数据回滚要求。
