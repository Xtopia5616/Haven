# ADR 0183：文件搜索工作量上限与异步根路径检查

## 状态

已接受（2026-09-20）

## 背景

限制遍历线程数只能降低单次搜索的资源占用，不能阻止对过宽根目录执行长时间的
无匹配扫描。此前搜索还在 async 调用路径上直接调用 `Path::exists()`；UNC 或慢速
磁盘的同步元数据调用会阻塞 Tokio worker。

## 决策

1. 每次文件搜索最多检查 100,000 个文件系统条目。达到上限时保留已收集结果，返回
   `has_more=true`、`truncated=true` 和缩小搜索范围的提示；结果上限与扫描工作上限
   使用不同的提示原因。
2. 根路径预检查使用可取消的 `tokio::fs::metadata`，确认路径是文件或目录后才进入
   blocking 搜索 worker。

## 替代方案

- 只限制结果数量：无匹配查询仍可能遍历整个磁盘，拒绝。
- 在 async 调用路径继续使用同步 `exists()`：本地盘通常没问题，但慢盘/网络盘会
  阻塞运行时，拒绝。
- 让调用方自行传入工作量上限：会扩大模型可见契约和配置面，当前固定安全上限足够。

## 影响、验证与回滚

搜索输入字段和正常结果结构不变；超大范围搜索现在可能提前返回部分结果，调用方可
根据 `has_more` 缩小 root、pattern 或 max_depth 后重试。无数据库、配置迁移；验证包括
文件搜索测试、严格 Clippy、格式化和 workspace 测试。回滚代码即可。
