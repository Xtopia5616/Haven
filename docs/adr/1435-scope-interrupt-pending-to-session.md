# ADR 1435：中断等待状态按会话隔离

## 状态

已实施 — 2026-10-27。

## 背景与证据

R12 后续复核发现，`ChatSessionController.interruptOutput` 用一个全局布尔值防重入，页面又把同一个等待状态传给当前 Composer。A 会话的中断 IPC 尚未返回时，切到 B 或新草稿会禁用其发送按钮，B 的中断也被直接忽略。A 的迟到成功通知还会把“输出已中断”显示在新的用户选择上。

## 决定与不变量

- Controller 按 session ID 持有在途中断集合，每个会话最多一个请求；不同会话可独立中断。
- 页面只接收集合的不可变数组投影，按当前活动会话派生 Composer 的等待状态。新草稿没有会话，不继承旧请求的等待状态。
- 请求结束只删除自己的会话；A 的 finally 不会清除 B 的等待状态。切走再切回 A 仍保留 A 的真实等待状态并阻止重复请求。
- 成功通知要求原用户选择版本和活动会话仍一致；失败继续经过已有错误通道报告，后端请求仍操作发起时的会话。
- 等待集合仅覆盖未完成 IPC，不持久化、不缓存历史会话，也不新增后台执行 owner。请求返回后立即释放条目。

## 替代方案与范围

切换时清空布尔值会允许同会话重复中断，且旧请求的 finally 仍会清除新请求状态。仅隔离通知不能恢复 B 的发送和中断能力。继续生成、rollback 和派生会话的等待状态不在本次切片改动范围，按后续源码证据独立复核。

现有 controller 测试超过职责复核阈值；本次保留共享 SessionReducer/command harness，验证真实选择代次和并发命令边界，不复制夹具另建一套选择状态。生产 owner 与模块依赖不变。

## 影响、回滚与重置

仅 UI 内部状态及回调变化，无 Rust、IPC、数据库、配置或持久事件变化，无需数据重置。回滚涉及 controller、页面投影和相应测试；回滚会重新引入跨会话阻塞。
