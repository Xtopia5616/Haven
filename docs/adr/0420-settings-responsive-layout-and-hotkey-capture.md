# ADR 0420：设置页自适应表单与快捷键录入

- 状态：已采纳（2026-10-01）
- 范围：设置页布局、全局录音快捷键录入交互

## 背景

设置页在受限窗口宽度下仍依赖视口断点和分类专属表单布局，控件容易拥挤。录入新的录音快捷键时，全局快捷键监听也会收到同一次按键，可能触发录音。

## 决定

1. 设置页主体使用统一的最大内容宽度和 CSS 容器查询。表单在内容宽度大于 640 CSS px 时采用标签/说明与控件两列布局，窄于该宽度时改为单列；分组卡片纵向填满内容区，选项网格按最小可读宽度自适应。
2. `HotkeyInput` 在开始、结束录入时通知所属设置页。结束录入、按键完成、取消、失焦或组件卸载都会清除录入态；设置页通过 `set_hotkey_capture_active` 同步进程内状态。
3. 全局快捷键回调在调度异步工作前、异步工作开始时各检查一次临时录入态；开启期间不触发录音。状态使用 `AppState` 中的原子布尔值，不写入配置或数据库。
4. Rust IPC handler、注册表、生成的 TypeScript 命令类型和 IPC 文档共同记录该命令；安全边界仅允许控制当前 renderer 的瞬时录入抑制状态。

## 替代方案

- 仅在前端捕获按键：无法阻止 Windows 全局快捷键回调同时触发录音。
- 暂时注销并重新注册全局快捷键：会引入原生快捷键生命周期与失败恢复路径；短期进程态标记足以屏蔽录入期间的事件。
- 继续使用视口媒体查询和各分类独立断点：侧栏改变设置内容可用宽度时无法准确反映拥挤程度，也会重复维护布局规则。

## 影响与验证

- 不改变录音快捷键配置格式、数据库或持久化状态；无数据重置要求。
- 前端测试覆盖录入成功、取消、失焦、卸载后的状态恢复；设置页测试覆盖 IPC 开启与关闭。IPC 检查脚本验证命令 handler、注册、类型、边界登记和文档一致。
- 验收命令：`cargo fmt --all -- --check`、`cargo check --workspace --locked`、`cargo clippy --workspace --locked -- -D warnings`、`cargo test --workspace --locked`、`corepack pnpm --dir ui run check`、`corepack pnpm --dir ui run test:run`、`corepack pnpm --dir ui run build` 及 IPC 契约检查。
- 设置内容以自身容器宽度切换布局；Windows 桌面交互仍可在 640 CSS px 两侧检查表单切换与快捷键录入期间的录音抑制。

## 回滚

删除录入态 IPC、设置页回调与全局快捷键检查，恢复此前设置页布局规则即可。无需重置用户数据。
