# ADR 0108：UI 上下文 token 指示与工具卡片完成态折叠

日期：2026-09-09
状态：已采纳

## 背景

聊天工具栏 token 指示器原先显示会话累计 token 总量，但紧邻的进度条只反映缓存命中率，数字与用户当前最需要关注的上下文占用并不一致。工具结果卡片在流式输出结束后仍保持展开，会让长对话中已经完成的工具结果持续占用垂直空间。

## 决定

1. token 指示器的主数字改为当前上下文 token 数；恢复历史会话时沿用最近一次持久化调用的上下文快照。单位显示为 `ctx`。
2. token 指示器下方的细进度条只表示当前缓存命中率，不再承载上下文窗口比例；完整上下文与缓存明细继续保留在原有弹窗中。
3. 工具卡片在输出期间保持展开，输出完成后自动折叠；完成态卡片首次渲染也默认折叠。用户手动展开或折叠后，在没有新的流式状态转换时保持该选择。
4. 仅调整前端展示状态，不修改 Tauri IPC、用量数据结构、数据库或工具结果内容。

## 替代方案

- 继续显示累计 token 总量：能体现会话成本，但不能直接回答当前上下文距离窗口上限还有多少，因此不采用。
- 完成后保留工具卡片展开：可以减少一次点击，但长会话的内容密度和扫描效率较差，因此不采用。
- 通过持续绑定 `open={streaming}` 控制卡片：会在用户手动操作或内容更新时覆盖用户选择，因此采用只响应流式状态转换的本地状态。

## 影响与验证

token 指示器仍使用既有 `buildTokenUsageDetails` 数据，缓存进度条和明细弹窗的其他内容保持不变。工具卡片继续使用 lazy body，折叠时不挂载正文；流式过程中仍即时渲染输出。

重点验证：

```text
corepack pnpm --dir ui run check
corepack pnpm --dir ui run test:run
corepack pnpm --dir ui run build
```

## 回滚与重置

回滚对应提交即可恢复原先的 token 主数字和工具卡片展开策略。无需数据库、配置或缓存重置。
