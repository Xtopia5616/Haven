# ADR 0430：待决交互可以收起并重新打开

- 状态：Accepted
- 日期：2026-10-03
- 关联：ADR 0423、ADR 0424、ADR 0428

## 背景

权限确认弹窗和 `ask` 问题都由交互生命周期拥有者维护为 pending。弹窗关闭会被当作拒绝，
问题卡片也没有便于暂时收起后恢复的入口；在长对话中，待操作内容容易离开视野。

## 决定

1. 关闭权限弹窗、点击遮罩或按 Escape 只收起 renderer 展示，不改变交互状态，也不提交拒绝。
   安全确认的期限仍继续生效；到期仍由现有超时流程拒绝。
2. pending `ask` 卡片可收起；收起不等同于“忽略”或回答，也保留已选选项。
3. 聊天输入框左下提供统一的“待操作”菜单，列出所有 pending 问题和确认。选择确认会重新打开
   对应弹窗；选择问题会切换到所属会话并滚动回问题卡片。
4. 拒绝分段按钮的展开控件采用错误色，明确其菜单也包含拒绝决定。

## 替代方案

- 把关闭继续当作拒绝会让暂时离开弹窗产生不可撤销的授权结果。
- 在会话中搜索原问题或确认气泡需要用户离开输入区并自行定位，无法提供稳定的恢复入口。

## 影响与重置

收起状态只存在于当前 renderer 内存中。交互 pending/resolved、超时、授权和 transcript 契约均不变；
重新启动后仍由会话恢复结果决定待决项目，无需重置数据。

## 验证

覆盖弹窗关闭后不决策且可重新显示、问题收起不忽略、待操作菜单可选择请求，以及拒绝展开控件
使用错误色；运行 UI 检查与测试和项目规定的完整门禁。
