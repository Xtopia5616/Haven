# ADR 0435：批量加载工具以稳定缓存前缀

## 状态

已接受（2026-10-03）。

## 背景

本机会话用量记录显示，模型的缓存 token 会在延迟工具加载后明显回落，并在工具面稳定后的连续请求中恢复。`tool_catalog.load` 每次成功都会改变 provider 的 `tools[]` 定义；分多轮逐步加载时，缓存服务需要针对多个不同请求前缀重新建立缓存。

当前 DeepSeek 上下文缓存由 provider 自动管理，依据重复的请求前缀工作；没有应用侧持久缓存开关可以强制命中。[DeepSeek Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)

## 决定

1. 模型提示应先收集当前可预见的 builtin 能力，再尽可能用一次 `tool_catalog(action=load)` 加载；精确 operation 放入 `operations`，需要完整 root 时放入 `roots`，两者可同时提供。
2. 只加载任务需要的能力。若超出 provider 工具预算，依据返回的选择列表缩小同一批次，不能为了缓存率预加载无关 schema。
3. 能力后续确实新增时仍允许再次加载；提示优化只减少可避免的工具面重建，不改变延迟加载、session 隔离、权限或预算契约。

## 替代方案

- 每轮预加载所有 builtin schema：拒绝，会重新引入随安装能力增长的请求开销，并违反按需延迟加载边界。
- 保持逐个加载的默认提示：拒绝，已知可用能力被分成多轮加载会产生额外请求和缓存前缀变化。
- 用一个通用 dispatcher 替换精确 operation schema：拒绝，改变模型可调用契约、授权和工具执行边界，范围远超本次缓存优化。

## 影响与验证

模型会更倾向于一次加载本轮已知需要的多个能力，减少额外往返和 provider 工具面变更。缓存命中仍由 provider 的前缀规则、可用缓存及请求内容决定，不能保证每次或累计命中率达到 90%。实现已核对 `ToolCatalogParams` 同时接受 `roots` 和 `operations`，loader 对二者求并集后按现有预算原子注册；自动门禁待运行。

## 回滚

回退本 ADR 的提示与目录说明即可。没有数据库、配置、IPC 或用户数据迁移。
