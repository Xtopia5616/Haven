# ADR 1178：限制并发 Skill 脚本执行容量

## 状态

已采纳并实施。

## 背景

单次 Skill 执行的脚本快照最多 16 MiB，stdout 和 stderr 分别保留最多 8 MiB；但多个 Skill 可以并行执行，单次上限不能约束同一个 Tools runtime 的聚合占用。脚本快照、捕获缓冲和子进程数量都随并发数增长。

## 决定

- 每个 composition-owned `SkillRunner` 最多同时执行 4 个 Skill。`SkillRunner::clone` 共用同一个并发信号量；等待槽位的时间计入该调用的总期限，并响应取消。
- 在取得执行槽后才创建脚本快照、准备 venv、启动子进程和保留输出；执行、清理或提前失败时 RAII 释放槽位。
- 固定容量不对用户开放配置，避免设置值绕过受控资源预算。排队中的调用继续使用现有 deadline/cancellation 结果。
- 四个槽位把该 runner 同时持有的脚本快照限制在最多 64 MiB，把两个管道的原始保留缓冲限制在最多 64 MiB。文本解码会造成短暂额外复制；该预算不限制 Python 进程自身内存、venv 安装体量、work directory 文件或另一个独立 Tools runtime 的容量，也不是操作系统文件系统沙箱。

## 替代方案

- 仅保留每次调用的单文件/单流上限：拒绝，无法约束并发聚合容量。
- 增加可由用户调整的并发设置：拒绝，当前没有预算协商或负载测量契约，任意增大可抵消单次上限。
- 仅限制子进程而不限制快照和输出捕获生命周期：拒绝，三类资源由同一次 Skill 执行共同持有，应该使用同一槽位。

## 影响与迁移

高于 4 个并发的 Skill 调用会排队，排队也消耗其总执行期限；现有超时与取消信号会在排队期间生效。单个 runner 的快照与管道保留容量有聚合上限；工作目录内容及脚本的进程内内存仍需由后续工作区和 OS 隔离设计评估。此为进程内策略变化，无持久数据变化，无需重置。

## 验证

- 并发测试同时启动 5 个不同 Skill，让脚本停留在明确等待点，验证恰有 4 个进入执行，随后释放并确认 5 个均完成且快照全部回收。
- 运行格式检查、Tools crate 全量测试和严格 Clippy。
