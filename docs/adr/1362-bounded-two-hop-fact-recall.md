# ADR 1362：有界两跳事实图召回

## 状态

已采纳 — 2026-10-21

## 背景

ADR 1357 让关键词或向量命中的事实沿 concept 节点扩展一跳。对于“用户在 Acme 工作”这样的种子，系统能召回 Acme 的总部事实，但不能继续沿“Acme 总部在 Seattle”关联 Seattle 的州等信息。直接放开递归遍历会让高连接节点放大查询、噪声和敏感路径风险。

## 决定

1. 事实召回只从已有关键词/向量事实命中开始，不做 LLM 查询分解或文本节点猜测；最多选择 16 个规范 `fact-*` 种子。
2. 只遍历 `kind='concept'` 的端点，不扩展通用 `user` 节点。每跳最多收集 16 个唯一概念节点，最大深度固定为两跳；第二跳只从通过共享可见性检查的一跳候选继续扩展，并跳过已扩展节点、种子事实和已有的一跳事实，避免回路与重复结果。
3. 每次图扩展的候选总上限为 80。最多 60 个槽位优先给一跳候选，最多 20 个槽位留给第二跳；查询较小或第二跳命中较少时，未使用槽位由更多一跳候选补足。两跳查询都在 SQL 中应用 fact subject 与 memory kind scope，再由共同可见性过滤拒绝敏感事实。
4. 每一跳内部按现有事实有效置信度、最近观察时间和稳定 ID 排序。直接关键词/向量命中优先于图扩展；初始一跳候选优先于第二跳候选，第二跳之后再用低排名的一跳候选补空位。MemoryRecall、IPC、embedding 和 schema 契约不变。

## 考虑过的方案

- 无界递归遍历：拒绝。高度连接节点会扩大扫描范围、噪声和敏感路径传播面。
- 每次只返回一跳，完全不继续扩展：拒绝。无法找回经一个中间实体连接的事实。
- LLM 分解召回查询：本切片不引入。它需要额外模型预算、分类/计划契约和失败降级规则，与确定性的图遍历边界不同。

## 后果

召回现在能沿最多两个事实关系带回跨实体上下文，但第二跳排序只表示图距离和事实有效分数，不等于与用户查询的语义相似度；直接关键词与向量结果仍负责表达查询相关性。图查询最多扩展 16 个种子、每跳 16 个节点、80 个总候选，并继续使用现有 SQLite subject/object 索引。没有数据迁移或旧库重置要求。

## 验收

- 一跳 subject/object 两侧关系仍可召回，且有两跳命中、三跳不继续扩展的测试。
- 隐藏敏感事实不能作为第二跳中间桥；类别、subject、种子 ID 和返回候选上限保持约束。
- 两跳合计不超过 80；直接命中、缺失种子、重复事实和空结果保持稳定。
- Memory 全量测试、格式与 workspace strict Clippy 通过。
