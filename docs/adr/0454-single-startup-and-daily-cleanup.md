# ADR 0454：合并启动与每日媒体清理

- 状态：Implemented
- 日期：2026-10-04
- 范围：AppState 启动时的会话保留、受管媒体和上传暂存清理
- 关联：ADR 0015

## 背景

应用原先分别启动一次会话/媒体清理、一次上传暂存清理，以及一个每日清理任务。Tokio `interval` 的首个 tick 立即就绪，因此每日任务在启动时又执行同一轮清理，重复扫描并可能与启动清理竞争删除。

## 决定

1. 使用同一个 cleanup pass 执行会话保留、受管媒体对账和独立 TTL 的上传暂存清理。
2. 一个 app-owned worker 先执行一次启动 pass，再从该 pass 完成后 24 小时开始周期扫描。
3. 保留 `history_retention_days == 0` 时的孤儿媒体扫描；附件引用查询失败时跳过媒体删除但仍执行独立暂存清理。

## 影响

启动扫描不再与立即触发的每日扫描重复运行。会话保留策略、活动 asset lease、附件引用 fail-closed 和暂存文件 TTL 不变。数据库、配置、IPC 与用户数据格式不变，无需重置。

## 验证

定向测试确认周期 interval 的首个 tick 不会在启动时发生。运行 app-binary 定向测试及 workspace 门禁。

## 回滚

若回滚，应保留启动清理并为每日周期设置延迟首 tick；不可恢复默认立即 tick，否则会重新产生冷启动重复清理。
