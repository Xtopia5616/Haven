# ADR 0818：拒绝用过期快照覆盖外部配置

## 状态

Accepted — 2026-10-08

## 背景

`ConfigService` 持有启动时加载的内存快照。若用户或维护工具在应用运行期间编辑 `config.toml`，下一次 Settings 保存会直接把旧快照原子替换到磁盘，静默丢失外部修改。应用此前只能靠人工记住“编辑后必须先重启”避免该问题。

## 决定

`ConfigLoader` 记录加载内容的进程内文件指纹。每次保存在替换文件前重新读取并比较；文件缺失或指纹已变化时删除临时文件并拒绝保存，让 `ConfigService` 回滚内存 mutation。错误明确提示重启以加载最新配置。指纹仅用于新鲜度比较，不承担安全或完整性证明。

## 替代方案

- 自动合并配置文件：拒绝。配置包含多层策略和凭据引用，文本或字段级合并可能破坏一致性。
- 静默重载后再应用旧 UI payload：拒绝。旧 Settings payload 可能只覆盖部分字段，无法可靠判定编辑意图。
- 仅依赖 UI 提示重启：拒绝。它不能阻止其他编辑器、同步软件或脚本造成的覆盖。

## 影响与验证

配置格式、凭据、数据库和设置 wire shape 不变；用户外部编辑后需要重启 Haven，不能继续从旧进程保存。回归覆盖外部编辑后拒绝 stale write、磁盘内容保持不变、内存快照与版本回滚。

适用门禁：`cargo fmt --all -- --check`、`cargo test --locked -p haven-common`、`cargo clippy --locked -p haven-common -- -D warnings`。

## 回滚

回滚指纹检查会恢复旧的覆盖行为，不涉及配置或数据库迁移。
